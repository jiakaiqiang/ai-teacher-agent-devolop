课程总览 课程资料

中国 AI 前端与 Agent 岗位动态

调研日期：2026-07-13
适用范围：中国大陆求职市场；AI 前端、AI 应用全栈、Agent 应用/平台方向
用途：决定 90 天课程的必修能力、项目证据和提交后的五连问，不用于推断招聘数量或薪资。

1. 证据边界

本报告按可信度使用证据：

等级 证据 可以支持的结论 不可以支持的结论
A 中国企业官方招聘页中的具体岗位 岗位职责、技术要求、工程侧重点 整个市场的占比、薪资中位数、岗位数量
B BOSS 直聘、猎聘等国内招聘平台的当前检索页 岗位名称和关键词仍在变化 无法稳定复现的 SPA 结果不能冒充定量统计
C 资源 目录中的国内 2026 面试 PDF 设计学习题、面试表达和故障实验 不能证明公司官方岗位、招聘真实性或市场频率
D 当前两个真实项目的代码和功能状态 判断学生能否产出可核验证据 不能替代真实企业生产年限

本轮主动排除 2026Newsbreak AI全栈工程师.pdf、2026海外岗前端AI架构师面试.pdf 等海外样本。海外岗位不得作为课程优先级的主证据。

本轮已逐页打开并核验下列四个仍可访问的中国企业官方岗位。其余无法稳定复核的搜索摘要不进入正式结论。

2. 国内官方岗位样本

官方岗位样本 明确要求 对课程的约束
字节跳动：AI 应用前端工程师-Aime 北京社招；JS/TS、React 或 Vue、Electron/Tauri、SSE/WebSocket、长任务状态与异常恢复、测试和 CI；职责含任务流、Tool Call、Generative UI、本地工具、权限确认、人工接管、MCP/Skill/插件 第一阶段首屏就是 Agent Run UI；必须覆盖流式、状态机、工具、审批、恢复和权限，普通聊天框不算 AI 前端作品
字节跳动：AgentOps 前端 上海社招；HTML/CSS/JS/TS、React、Node.js、平台稳定性和研发体验；职责含开发调试、评测、可观测和分析；Prompt/RAG/Agent 为加分项 必须有 Node/BFF、Eval、Trace、质量指标和平台化证据；只做业务页面不能覆盖 AgentOps 岗
阿里云：AI 前端开发工程师 2027 届实习，北京/广州/杭州，页面更新 2026-04-21；LLM/Agent/Prompt/Skill、AI Coding、React+TS、Node/BFF/SSR 和独立解决 AI 应用问题 AI Coding 已进入明确要求，但必须用人工审查和测试证明；课程保留 Node/BFF，并把 React 记为投递覆盖风险

四个样本不足以做市场占比统计，但交叉出现的共同方向很清楚：TypeScript/现代工程化仍是底座；Agent UI 远超聊天框；前端职责向 Node/BFF 或后端扩张；测试、CI/CD、性能、安全、评测和可观测性进入正式职责。Electron/桌面、本地权限、MCP/Skill、Generative UI 和 AgentOps 是明显增强的方向，但是否设为必修要按目标岗位二次筛选。

3. 中国市场的能力分层

第一优先级：AI 前端求职的硬底座

  1. JavaScript/TypeScript、浏览器、异步与性能原理，而不是只会框架 API。
  2. Vue/React 至少一种主框架的工程化能力，以及组件、状态、路由、测试、构建和发布。
  3. SSE/WebSocket/ReadableStream、UTF-8 分片、取消、重连、补偿和背压。
  4. Agent 事件合同、执行状态机、Tool Call 时间线、HITL 审批和错误恢复。
  5. Markdown/长文本/引用/多模态结果的安全与性能，尤其是 XSS、虚拟化和自动滚动。
  6. Node/BFF 协作、接口与数据模型、鉴权、日志、CI/CD 和监控。
  7. 若目标是桌面 Agent：Electron/Tauri、IPC、本地文件/终端/浏览器能力、权限和沙箱。

第二优先级：从 AI 前端转 AI 全栈

  1. NestJS 模块边界、SQL/事务/索引、Postgres、Redis、BullMQ、幂等与恢复。
  2. Python/FastAPI、类型、异步、测试和模型 Provider Adapter。
  3. Prompt/Context Engineering、Structured Output、RAG 摄取/召回/引用。
  4. Eval 黄金集、Recall@k/MRR、忠实度、人工复核和回归门禁。
  5. 多租户、资源级权限、审计、Docker、Trace、成本和 SLO。

第三优先级：Agent 应用/平台转型

  1. Runtime Adapter、Tool Registry/Capability、MCP、ContextEnvelope 和预算终止。
  2. Durable HITL、Workflow/DAG、任务队列、幂等、恢复和冲突处理。
  3. Memory 与 RAG 的职责边界、写入确认、权限和检索评测。
  4. 多 Agent 委派、责任链、独立 Validation Agent 和 Artifact handoff。
  5. Trajectory Eval、Replay、A/B、OpenTelemetry、Chaos、成本与生产就绪评审。

趋势加分项，不应挤占当前主线

  • Generative UI、协议/DSL 驱动渲染、插件/Skill 动态加载。
  • WebGPU、浏览器本地模型、WASM Embedding。
  • 多模态交互、AI UI Kit、可视化 Workflow Canvas。
  • 更复杂的 Agent 自主规划。

这些方向可以作为作品亮点，但在流式恢复、合同、权限、Eval 和独立排障没有过关前，不应提前投入。

5. 对当前用户路线的判断

路线“AI 前端 -> AI 全栈 -> AI Agent 工程”符合能力依赖：前端先解决交互、事件、状态和工程交付；随后补数据、事务、Python、RAG 和 Eval；最后进入 Runtime、MCP、Workflow、多 Agent 和生产治理。

当前用户已有高级 Vue 前端、可视化、性能、工程化、AI Coding 和多 Agent 使用经验，适合从 AI 前端架构增量开始；后端刚起步，因此 Day 21-60 必须设置 SQL、事务、鉴权、队列和 Python 的独立门禁，不能因为 AI 能生成后端代码就跳级。

React 风险

本轮四个官方样本中，Aime 接受 React 或 Vue，AgentOps 和阿里云样本明确写 React。样本量不能代表全市场比例，但足以证明 Vue-only 会缩小可投岗位。用户已要求前 60 天不涉及 React，因此课程保持 Vue 3，并聚焦框架无关的流式、事件、状态、Agent UI、Eval UI 和全栈能力；不承诺覆盖全部 AI 前端岗位。

Day 59 和 Day 89 必须分别用目标城市、目标公司和实际投递岗位重新统计：若目标岗位明显偏 React/Next.js，应在 90 天后安排 2-3 周迁移训练，而不是在当前主线中途打断后端基础。若目标岗位集中在 Aime/WorkBuddy 一类桌面智能体，还需增加 Electron、IPC、本地权限与沙箱专项。

6. 对课程的硬性调整

  1. Day 1-20 每天必须产生 AI 前端证据，不能退化为普通 Vue 页面。
  2. Day 14 只能演进 Day 1 的 AgentEvent，不得重新定义第二套事件协议。
  3. Day 21 从 NestJS 模块边界和 DI 深化开始，不重复 Controller/Service 入门。
  4. Day 31 是 Tool Registry v2 治理；Day 33 是可持久化 HITL，均不得重复早期功能。
  5. Day 41 的 Python 服务必须立即被 NestJS 调用，禁止孤立教程项目。
  6. RAG 在实现检索时同步建立人工标注集，Eval 不是功能做完后的装饰。
  7. Agent 阶段改用从零构建的 p2-agent-workbench：以模块化单体完成最小主链路，再逐步增加 MCP、Human、RAG、受控委派和 Eval；不借用大型平台已有能力冒充学习成果。
  8. 每天保留“人做语义/架构/安全/验收，AI 做检索/骨架/测试候选/Reviewer”的分工和独立考试。

7. 动态刷新规则

  • 每周至少复查一次中国企业官方招聘页，记录岗位 URL、发布日期/抓取日、城市、年限、框架、后端、AI/Agent、工程化关键词。
  • 只有可打开的具体 JD 才进入 A 级证据；招聘平台搜索摘要仅作为待核验线索。
  • 每两周计算一次目标岗位覆盖矩阵，不把单一公司的要求推广成整个市场。
  • Day 59 做 AI 前端/全栈投递校准，Day 89 做 Agent 岗位校准，并据此调整项目叙事和下一阶段补课。
  • Day 59 即启动首轮投递和面试反馈记录，不能等 10 月 11 日课程结束后才开始求职。
  • 招聘要求变化只调整任务深度和证据，不推翻“真实项目 + 原理 + 反证 + 独立门禁”的教学方法。
