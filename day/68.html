课程总览 第 10 周

Day 68

Day 68 - 多 Agent Memory/RAG 基线

《90 天拆分规则说明》校正口径（Day 68 权威执行口径）

  • 阶段定位：阶段三（Day61-90，AI 全栈 -> AI Agent 工程师），所有增量进入 p2-agent-workbench 用户主链路。
  • 完整模块：共享事实、角色临时记忆与 RAG 基线；代码落点为 backend/app/memory/service.py、retrieval.py、frontend/src/features/memory、tests/day68，必须能运行、能测试、能观察结果。
  • v1：用关键词检索 20 条标注样本；v2：分离 shared facts 与 role scratchpad，并记录来源/TTL；v3：加入更正、删除、跨 Session 隔离和 Handoff 检索证据。三版都要保留真实运行证据，并说明后一版修复的具体痛点。
  • 累积复用：输入是 Day67 的 Artifact 与 validator 证据门禁；本日输出直接交给 Day69 的 worktree 隔离和受限 DAG，禁止新建无关 Demo。
  • 时间盒：本日是周末扩展日：90 分钟阅读 + 90 分钟动手完成基线，再增加 180 分钟动手深化（合计 270 分钟动手）；深化用于 v3、故障注入、架构证据和复盘。
  • 硬门槛：完成 Recall@5 基线、过期/删除、事实更正、角色隔离和空召回；提交真实 diff、命令输出、架构证据、学习日志和 AI Review，未运行或无证据的内容不得标记完成。

v1 -> v2 -> v3 执行步骤

  1. v1 最小闭环：用关键词检索 20 条标注样本。先写失败测试，再实现最短用户链路；checkpoint 是一次 Run 有确定终态和 traceId。
  2. v2 关键加层：分离 shared facts 与 role scratchpad，并记录来源/TTL。复用 v1 合同，不复制旁路实现；checkpoint 是正常、边界和权限/重放测试可重复。
  3. v3 生产约束：加入更正、删除、跨 Session 隔离和 Handoff 检索证据。补取消、超时、审计、恢复或发布门禁；checkpoint 是故障后没有静默成功和重复副作用。
  4. 运行命令：在 D:\demo\ai-techer\p2-agent-workbench 执行 uv run pytest tests/day68 -q；涉及前端时再执行 pnpm --dir frontend test -- --run day68。实际命令和输出写入 evidence/day68/。

必做测试与两个反证

  • 测试范围：Recall@5 基线、过期/删除、事实更正、角色隔离和空召回；至少覆盖正常、边界、权限或并发/重放、恢复中的三类。
  • 反证 1：把 scratchpad 写入共享事实后切换角色，泄漏测试必须失败。记录复现步骤、可观察信号、恢复动作和恢复后测试。
  • 反证 2：删除 TTL/删除传播后重放已撤回事实，检索测试必须阻止旧事实进入 Handoff。记录复现步骤、可观察信号、恢复动作和恢复后测试。

跨 Day 导航

  • 前置复用：Day67 的 Artifact 与 validator 证据门禁。
  • 本日交付：共享事实、角色临时记忆与 RAG 基线。
  • 后续消费：Day69 的 worktree 隔离和受限 DAG。

日期与时长：09-19 周六 6h
项目：D:\demo\ai-techer\p2-agent-workbench
Runtime 基线：Agent 角色通过本机 Codex CLI / Claude Code CLI 执行；后端只调用服务端 allowlist 命令模板，不直接调用模型 HTTP API，不使用危险权限绕过参数。
阶段任务性质：教师基线；实际分发时根据上一日成绩生成补弱版、标准版或挑战版。

今日目标

区分多角色共享事实、角色临时上下文、长期记忆与 RAG；建立 20 条查询的关键词召回基线和可审计写入策略。

必须掌握的知识

共享事实、角色 scratchpad、长期 Memory、RAG/Context 边界、写入确认、隐私

学习时必须讲清每个概念解决的问题、运行机制、项目落点、生产误区和验证方法，不能只记 API。

真实项目任务

建立多角色共享事实索引、关键词检索基线和 Memory 写入策略

禁止新建与主项目无关的 Demo；当天改动必须进入真实用户链路或真实平台合同。

原理反证与架构证据

多角色记忆生命周期图；scratchpad 泄漏、冲突事实、无关命中、越权知识库

人与 AI 分工

人定义共享/临时/长期边界和标签；AI 生成对照查询与冲突样本

任何 AI 生成内容都要记录接受、修改或拒绝理由。核心合同、状态机、权限、Eval 标签和最终验收由人负责。

时间盒

本日为周末扩展日：90 分钟阅读 + 90 分钟动手完成基线，再增加 180 分钟动手深化（合计 270 分钟动手）。阅读用于原理、源码和边界；动手用于 v1/v2/v3、测试、故障注入、架构证据与复盘。

通过标准

至少 20 条查询并输出 Recall@K/MRR；角色 scratchpad 不跨任务；未确认内容不入长期记忆

完成后提交 commit、测试输出、学习日志、架构证据和 AI Review 记录，先回答本文件的三道课末核心问题；项目初检通过后再进入教师五连问。

课末 3 个核心问题

  1. 请区分共享事实索引、coordinator/executor/validator scratchpad、长期 Memory 和 RAG 语料的所有权、TTL 与召回边界；一个 Agent 的推测怎样经过确认才能成为其他角色可用事实？
  2. 如果故意移除今天最关键的保护机制，线上会出现什么可观察现象？请给出最小复现、定位证据、恢复动作和一条防复发测试。
  3. 请引用今天的具体代码、测试和架构证据，证明项目目标已经达到；再说明当前实现距离企业生产标准还缺什么，下一步如何演进而不破坏已有合同。

真实项目情境题（联网更新 2026-07-13）

以下是依据当前中国岗位职责和官方技术机制构造的教学模拟，不代表来源企业真实发生过相同事故。题目中的规模和指标是练习约束，不是本项目已经取得的生产数据。

  1. 教学模拟：coordinator、executor、validator 共用检索缓存，validator 的失败推理 scratchpad 被下一个 executor 当成已确认事实。请按五段式给出 memory_scope、task_id、source_role、缓存和审计证据，隔离角色临时记忆，修复共享事实准入，验证跨任务攻击查询，并演进 Memory/RAG 治理。 依据：LangGraph Persistence
  2. 教学模拟：coordinator 把用户一句“这次先跳过测试”写成长期偏好，后续 executor 都尝试绕过验证；另有 Prompt Injection 诱导写入虚假权限。请按五段式定位写入来源和确认人，冻结可疑记忆，修复写入确认、TTL 与安全标签，验证冲突偏好，并演进可解释长期 Store。 依据：OWASP LLM Top 10 知识映射：Day 68：共享事实、角色临时记忆、长期记忆、RAG 边界、写入确认与隐私。
