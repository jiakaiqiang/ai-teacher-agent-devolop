课程总览 第 12 周

Day 83

Day 83 - 并行冲突/Handoff

《90 天拆分规则说明》校正口径（Day 83 权威执行口径）

  • 阶段定位：阶段三（Day61-90，AI 全栈 -> AI Agent 工程师），动态委派、验证与治理都服务于同一个 p2-agent-workbench 主链路。
  • 完整模块：并行 ChangeSet 冲突、base hash 与 Artifact 交接；代码落点为 backend/app/domain/change_set.py、orchestrator/merge_gate.py、tests/day83，必须能运行、能测试、能观察结果。
  • v1：两个 executor 在独立 worktree 修改不相交文件；v2：加入 base hash、Artifact manifest 和 Handoff 验收；v3：检测文本/语义冲突、阻止静默覆盖并支持人工解决后重放。三版都要保留真实运行证据，并说明后一版修复的具体痛点。
  • 累积复用：输入是 Day82 的单 owner、lease 和任务级队列；本日输出直接交给 Day84 的对抗 Validation Agent。
  • 时间盒：本日是周末扩展日：90 分钟阅读 + 90 分钟动手完成基线，再增加 180 分钟动手深化（合计 270 分钟动手）；深化用于 v3、故障注入、架构证据和复盘。
  • 硬门槛：完成 无冲突合并、同文件冲突、base 漂移、缺 Artifact、失败传播和清理恢复；提交真实 diff、命令输出、架构证据、学习日志和 AI Review，未运行或无证据的内容不得标记完成。

v1 -> v2 -> v3 执行步骤

  1. v1 最小闭环：两个 executor 在独立 worktree 修改不相交文件。先写失败测试，再完成最短用户链路；checkpoint 是一次任务有确定终态、owner 和 traceId。
  2. v2 关键加层：加入 base hash、Artifact manifest 和 Handoff 验收。复用 v1 合同；checkpoint 是正常、边界和权限/并发测试可重复。
  3. v3 生产约束：检测文本/语义冲突、阻止静默覆盖并支持人工解决后重放。补预算、审计、恢复、Eval 或发布门禁；checkpoint 是故障后无静默成功、越权和重复副作用。
  4. 运行命令：在 D:\demo\ai-techer\p2-agent-workbench 执行 uv run pytest tests/day83 -q；涉及前端时再执行 pnpm --dir frontend test -- --run day83。实际命令和输出写入 evidence/day83/。

必做测试与两个反证

  • 测试范围：无冲突合并、同文件冲突、base 漂移、缺 Artifact、失败传播和清理恢复；至少覆盖正常、边界、权限或并发/重放、恢复中的三类。
  • 反证 1：关闭冲突检测并让两个 executor 改同一行，测试必须捕获静默覆盖。记录复现步骤、可观察信号、恢复动作和恢复后测试。
  • 反证 2：删除 Artifact manifest 校验后交接缺文件，validator 必须拒绝完成。记录复现步骤、可观察信号、恢复动作和恢复后测试。

跨 Day 导航

  • 前置复用：Day82 的单 owner、lease 和任务级队列。
  • 本日交付：并行 ChangeSet 冲突、base hash 与 Artifact 交接。
  • 后续消费：Day84 的对抗 Validation Agent。

日期与时长：10-04 周日 6h
项目：D:\demo\ai-techer\p2-agent-workbench
Runtime 基线：Agent 角色通过本机 Codex CLI / Claude Code CLI 执行；后端只调用服务端 allowlist 命令模板，不直接调用模型 HTTP API，不使用危险权限绕过参数。
阶段任务性质：教师基线；实际分发时根据上一日成绩生成补弱版、标准版或挑战版。

今日目标

文件冲突、base hash 和 Artifact 交接；冲突不得静默覆盖。

必须掌握的知识

文件冲突、Artifact handoff、base hash、合并策略

学习时必须讲清每个概念解决的问题、运行机制、项目落点、生产误区和验证方法，不能只记 API。

真实项目任务

加固并行 Agent 产物交接

禁止新建与主项目无关的 Demo；当天改动必须进入真实用户链路或真实平台合同。

原理反证与架构证据

冲突 ADR；两 Agent 改同文件、旧 hash 写回

人与 AI 分工

人定冲突策略并处理真实冲突；AI 造场景

任何 AI 生成内容都要记录接受、修改或拒绝理由。核心合同、状态机、权限、Eval 标签和最终验收由人负责。

时间盒

本日为周末扩展日：90 分钟阅读 + 90 分钟动手完成基线，再增加 180 分钟动手深化（合计 270 分钟动手）。阅读用于原理、源码和边界；动手用于 v1/v2/v3、测试、故障注入、架构证据与复盘。

通过标准

冲突不静默覆盖；handoff 含上下文/产物/验证/风险

完成后提交 commit、测试输出、学习日志、架构证据和 AI Review 记录，先回答本文件的三道课末核心问题；项目初检通过后再进入教师五连问。

课末 3 个核心问题

  1. 请从今天项目的真实入口到最终输出，解释“并行冲突/Handoff”的数据流或控制流；当天知识链“文件冲突、Artifact handoff、base hash、合并策略”分别在哪一层起作用，为什么按这个顺序学习？
  2. 如果故意移除今天最关键的保护机制，线上会出现什么可观察现象？请给出最小复现、定位证据、恢复动作和一条防复发测试。
  3. 请引用今天的具体代码、测试和架构证据，证明项目目标已经达到；再说明当前实现距离企业生产标准还缺什么，下一步如何演进而不破坏已有合同。

真实项目情境题（联网更新 2026-07-13）

以下是依据当前中国岗位职责和官方技术机制构造的教学模拟，不代表来源企业真实发生过相同事故。题目中的规模和指标是练习约束，不是本项目已经取得的生产数据。

  1. 教学模拟：Codex 与 Claude 两个 executor 在独立 worktree 修改 60 个文件；两者基于同一旧 base hash 修改配置，后合并者静默覆盖前者。请按五段式给出 Runtime、worktree、commit/base hash 和 Handoff 证据，停止自动合并、修复冲突检测、验证真实冲突，并演进 Artifact 协议。 依据：S4 WorkBuddy
  2. 教学模拟：上游 Agent 只交付 diff，没有上下文、测试结果和已知风险；Validation Agent 误判通过，部署后 14 个 E2E 失败。请按五段式定位证据缺口、回滚止损、修复 handoff schema、验证门禁，并演进可追责产物链。 依据：S6 Harness 知识映射：Day 83：文件冲突、base hash、Artifact handoff 与合并策略。

完成后教师五连问

学生提交 commit、测试输出、学习日志、反证记录和架构证据后，教师依据真实 diff 按“局部机制 -> 边界一致性 -> 线上事故 -> 工程权衡 -> 架构演进”现场提出 5 道问题。五连问不预先固定，也不由下面的 PDF 题替代；评分规则见《AI 教师五连问验收协议》。
