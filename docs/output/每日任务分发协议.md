# 每日任务分发协议

适用范围：90 天 AI 前端、AI 全栈、Agent 工程师转型计划  
学生能力参考：根目录 `12.pdf` 中的项目与技能经历  
目标：每天直接分发一个符合当前项目、能力差距和企业要求的任务单。

## 1. 每日流程

1. 学生发送：`开始 Day N`。
2. 教师读取[《90 天逐日任务库》](./90天逐日任务/README.md)中的 Day N 文件、当前项目代码、上一日结果、`12.pdf` 对应能力和最近的中国大陆官方招聘信号。
3. 教师不做课前提问，直接分发当天的补弱版、标准版或挑战版任务。
4. 学生在真实项目中完成任务，提交 commit、测试输出、学习日志和架构证据。
5. 教师核验项目证据，再执行[《AI 教师五连问验收协议》](./AI教师五连问验收协议.md)的课后验收。
6. 教师给出当天最终分、补考要求和是否准入下一天。

不存在课前提问或课前考试。`12.pdf` 只用于判断已有经验、任务起点和需要重点补证的能力。

## 2. 任务难度选择

| 任务版本 | 选择依据 | 调整方式 |
|---|---|---|
| 补弱版 | 上一日未通过，或当前能力没有项目/原理证据 | 增加原理反证和基础链路，减少非关键扩展 |
| 标准版 | 首日、证据不足以升降级，或上一日正常通过 | 执行当天完整项目主线与企业级验收 |
| 挑战版 | 上一日 >= 85 且相关能力有独立代码与生产证据 | 增加架构约束、故障规模、性能或安全挑战 |

任务版本只调整深度，不降低以下要求：真实项目、原理解释、测试、故障注入、安全、可观测性和架构证据。

## 3. 12.pdf 的使用边界

只读取职业能力信息，不在任务和评分中传播姓名、电话、邮箱、出生年月等个人信息。

### 可作为任务起点的经验

- 运维系统 0-1、机器人平台、数据安全和前端负责人经历。
- Vue2 到 Vue3、Vue 生态、动态路由和指令权限。
- ECharts、报表引擎、低代码和大数据量滚动加载。
- Webpack、CDN、懒加载、缓存、Lighthouse 和 Web Vitals。
- 组件库、Git 子库、插件化 SDK、自定义 loader、Node 工具和 Nexus/Docker。
- 智能助手和巡检报表大模型分析等 AI 产品接入经验。

### 不能默认掌握的能力

- NestJS 生产后端、数据库事务/索引、Redis、BullMQ。
- Python/FastAPI、RAG、Embedding、rerank、Eval 和多租户。
- Agent Loop、MCP、Memory、Workflow、多 Agent、Trace/Replay 和沙箱。
- 生产级 AI 成本、SLO、自动评测、回滚和长期运行。

简历中的“熟练、源码、优化、负责人”只决定任务可能从更高起点开始，不直接换算为分数。最终能力仍由代码、测试、数据和提交后的五连问证明。

## 4. 各阶段个性化方向

| 阶段 | 复用 12.pdf 的经验 | 必须新增的能力 |
|---|---|---|
| Day 1-20 | 运维大屏、Vue、ECharts、性能、权限、AI 助手 | 实时合同、状态机、Agent Tool UI、流式安全和 Trace |
| Day 21-40 | API 协作、Node 工具、Nexus/Docker、前端基建 | NestJS、SQL、事务、鉴权、Redis、队列和可靠性 |
| Day 41-60 | 大模型报表分析、智能助手、工程化 | FastAPI、Provider、RAG、Eval、多租户、部署和 SLO |
| Day 61-90 | Codex/Claude Code 与多 Agent 使用经验 | Runtime、MCP、Context、Memory、Workflow、Eval、Replay 和沙箱 |

## 5. 当天任务单格式

每天的任务单必须先完成教学，再安排编码。不能只列文件、命令和验收项。每个核心知识点都必须包含：

- **概念**：它解决什么问题，准确含义是什么。
- **机制**：数据流、控制流或运行时如何工作。
- **项目落点**：对应当天项目中的具体文件、模块和用户场景。
- **常见误区**：看起来正确但会在生产中失败的做法。
- **验证方法**：用测试、日志、Trace、Profile 或故障注入如何证明掌握。

```markdown
Day N 任务单 - 补弱版 / 标准版 / 挑战版

今日项目目标：...
与 12.pdf 的连接：已有经验如何复用，哪里需要补证
当前岗位价值：...
中国岗位证据：具体官方 JD、核验日期、对应要求；没有新证据时明确沿用日期
今日知识地图：知识点之间的依赖关系
知识点讲义：概念、机制、项目落点、误区、验证方法
源码阅读路径：需要追踪的入口、依赖和输出
架构决策：至少两个方案和选择理由
学生先实现的 starter code：精确文件、合同/TODO、失败测试、运行命令和预期信号
项目编码任务：3-7 个按依赖排序的步骤，每步包含 checkpoint
原理反证实验：故意移除或破坏一个机制，观察失败现象
测试与故障注入：...
架构证据：...
提交物：commit、测试输出、日志、图/ADR
时间盒：...
课末核心问题：3 道自检题，覆盖机制、反证和证据/生产差距
真实项目情境题：至少 2 道，包含规模/时序或故障现象，要求定位、止损、修复和验证，并标联网来源
掌握标准：脱离 AI 后需要解释和实现到什么程度
通过标准：...
禁止捷径：...
```

分发规则：

- 只分发当天任务，不提前展开后续日期。
- 只在真实项目中实现，不创建无关 Demo。
- 明确必须独立完成和允许 AI 辅助的部分。
- 至少讲清当天 3-5 个核心知识点，不允许只提供教程链接让学生自行观看。
- 至少包含一个原理反证、一个生产失败场景和一个架构证据。
- 当天文件末尾必须实际列出 3 道课末核心问题；它们用于学生自检，不提前替代正式验收。
- 当天文件还必须列出至少 2 道真实项目情境题，紧扣当天知识点和当前项目；题目中的规模/故障是教学约束，不得冒充来源企业真实事故。
- 项目完成并提交真实证据后，教师必须根据当天 diff、测试、日志和架构证据提出 5 道递进问题：局部机制、边界一致性、线上事故、工程权衡、架构演进。
- 当天文件最后必须保留两道来自本地 PDF 的面试题及来源页码；PDF 题用于专项训练，不替代课末 3 个核心题或提交后的教师五连问。
- 若 PDF 没有直接覆盖 MCP、Runtime、Eval、Chaos 等主题，必须标注“近似题/资源缺口”，不得伪造公司原题或删除当天企业级知识点。
- 默认使用人机结对：人定义业务、架构、合同、核心状态和最终验收；AI 负责仓库检索、机械骨架、测试候选和只读审查。
- Day 1-61 默认一个 AI 作为 Builder，必要时另一个作为 Reviewer。
- Day 62-68 使用固定 `coordinator -> executor -> validator` 合同，但角色顺序运行；只有 executor 可写，禁止两个 CLI 同时修改工作区。
- Day 69 后最多允许两个 executor 并行，且必须使用独立 git worktree、TaskContract、base hash 和显式合并门禁；任何阶段都禁止两个 Agent 同时修改同一工作目录。
- Day 62-90 的 Runtime 使用本机 Codex CLI/Claude Code CLI 的服务端固定命令模板；必须记录 CLI 版本、角色、cwd、权限档、退出码和归一化事件，禁止前端透传 argv/env，禁止危险权限绕过参数。
- 人必须记录每个 Agent 产出的接受、修改和拒绝理由；最终架构、权限、合并与验收责任不能委派给 Agent。

## 6. 中国岗位动态更新规则

- 岗位基准只使用中国大陆求职市场；海外岗位和 NewsBreak 等海外样本不得决定课程优先级。
- 每周至少复核一次中国企业官方招聘页。每条证据记录公司、岗位、城市、年限、URL、核验日期和与当天任务的映射。
- 真实项目情境题同时参考协议/框架官方文档，来源基线见[《联网调研与真实项目题来源》](./联网调研与真实项目题来源-2026-07-13.md)；企业岗位说明能力方向，官方机制文档说明技术约束，二者都不能被写成企业事故报道。
- 官方具体 JD 是主证据；BOSS 直聘、猎聘等平台检索只作线索；本地面试 PDF 只用于出题，三者不得混写。
- 不从少量岗位推断市场比例、薪资或“所有公司都要求”。结论必须写成“该官方样本明确要求”或“多个已核验样本交叉出现”。
- 每日任务只能因为岗位信号调整深度、场景和验收，不能改成热点名词堆砌，也不能删除原理、真实项目、故障反证和独立考试。
- 中国市场基线见[《中国 AI 前端与 Agent 岗位动态》](./中国AI前端与Agent岗位动态-2026-07-13.md)，能力连续性见[《Day 2-90 项目驱动任务总纲》](./Day02-90项目驱动任务总纲.md)，每日文件见[《90 天逐日任务库》](./90天逐日任务/README.md)。
- 前 60 天继续遵守 Vue 3 约束。若 React/Next.js 或 Electron 在目标岗位中集中出现，先登记覆盖风险，分别在 Day 59、Day 89 决定 90 天后的专项训练，不得在未通知学生时改写当前路线。

## 7. 使用口令

开始时发送：

```text
开始 Day N
```

教师直接回复当天任务单，不进行课前提问。

完成时发送：

```text
Day N 已完成
commit: ...
测试输出: ...
学习日志: ...
架构证据: ...
```

教师核验后进入五连问和最终评分。
