# AI 教师五连问验收协议

生效版本：2026-07-13  
适用范围：90 天 AI 前端、AI 全栈、Agent 工程转型课程  
触发条件：学生提交 `Day N 已完成`、commit、测试输出、学习日志、反证记录和架构证据，且项目初检通过。

## 1. 为什么不是提前公布五道固定题

五连问用于判断学生是否真正理解当天自己写的代码。教师必须先读取实际 diff、测试、日志、Trace/指标和 ADR，再生成问题。提前写死答案只会训练背诵，不能验证线上问题解决能力。

任务文件末尾的 3 个“课末核心题”和至少 2 个“真实项目情境题”是学生编码后自检；本地 PDF 的 2 道题是面试复习；提交后的五连问才是当天评分门禁，三者不能互相替代。

## 2. 五道问题的递进结构

### 第一问：局部机制

从当天最小知识点或一段核心代码开始，要求解释：

- 输入、输出、状态所有者和调用时机；
- 运行时真实发生了什么；
- 一个容易写错的边界；
- 用哪条测试证明。

问题不能只问名词定义，必须引用当天具体文件、函数、事件或 SQL。

### 第二问：边界、并发与一致性

把第一问放大到并发、乱序、重放、取消、超时、事务、权限或资源释放场景，要求学生预测可观察现象，并说明正确的不变量。

### 第三问：线上真实事故

给出明确现象和约束，例如 P95 上升、重复执行、跨租户数据、流式中断、队列积压、模型 429 或工具超时。回答必须覆盖：

1. 先看哪些日志、指标和 Trace；
2. 如何缩小故障域；
3. 如何临时止损；
4. 如何确认根因；
5. 修复后如何验证。

### 第四问：工程权衡

要求比较至少两个方案，并从可靠性、性能、安全、成本、复杂度、可观测性和演进成本中选择至少三项进行权衡。不能用“最佳实践”“框架推荐”代替当前项目约束。

### 第五问：高层架构与治理

改变一个生产约束，例如流量十倍、模型不可用、跨租户、成本减半、团队拆分或合规审计，要求给出：

- 目标架构和边界变化；
- 兼容迁移步骤；
- 灰度、回滚和数据修复；
- SLI/SLO、Eval 或安全门禁；
- 哪些部分暂时不做及重审条件。

最后一问必须从“如何修代码”提升到“如何管理变化和风险”。

## 3. 出题证据优先级

| 证据 | 权重 | 使用规则 |
|---|---:|---|
| 当天真实 diff、测试和失败记录 | 35% | 至少三问必须直接引用 |
| 知识点重要性和前后依赖 | 25% | 不能跳过当天主链路 |
| 中国岗位要求 | 20% | 使用最近核验的杭州/苏州/西安 JD 或企业官方岗位 |
| 企业生产经验 | 15% | 故障、容量、安全、发布、回滚、观测 |
| `12.pdf` 的能力差距 | 5% | 优先补原理、证据和后端边界，不传播隐私 |

正式五连问中至少 3 问必须改写或加深当天真实项目情境题，并引用学生实际 diff、日志或指标，不能原样复述预设题目。

PDF 题只能作为问题线索。公司名 PDF 不得宣称为官方原题；MCP、Eval、Chaos 等资源缺口必须使用官方协议、源码和项目实验补足。

## 4. 每阶段五连问重点

| 阶段 | 第一/二问 | 第三问 | 第四/五问 |
|---|---|---|---|
| Day 1-20 | TS/Vue、事件、状态、WS/SSE、Tool UI | 竞态、断流、重复事件、XSS、性能 | Agent UI 边界、可观测性、生成式 UI 演进 |
| Day 21-40 | NestJS、API、SQL、事务、鉴权、缓存、队列 | 越权、慢查询、积压、重复任务、恢复 | BFF/服务边界、数据一致性、容量与发布 |
| Day 41-60 | Python、Provider、RAG、引用、Eval | 模型失败、检索退化、租户泄漏、回滚 | 模型治理、Eval 门禁、SLO 与成本 |

## 5. 评分

每日总分 100：项目证据 70 分 + 五连问 30 分。五道题每题 6 分：

| 分数 | 回答质量 |
|---:|---|
| 0-1 | 名词堆砌、结论错误、无法指向当天代码 |
| 2-3 | 概念基本正确，但缺因果、边界或验证 |
| 4 | 能联系代码和测试，能处理基础生产场景 |
| 5 | 因果完整，包含定位、取舍、验证和防复发 |
| 6 | 能识别隐藏假设，以数据比较方案并给出迁移/回滚 |

通过条件：

- 项目证据至少 49/70；
- 五连问至少 21/30；
- 每题至少 4/6；
- 第三问必须有止损、定位、修复、验证；
- 第五问必须有迁移、回滚和可量化门禁。

泛化答案即使概念正确，单题最高 3 分。核心代码无法解释，项目对应项计 0 分。

## 6. 教师出题格式

```markdown
Day N 五连问（关闭 AI 和搜索，连续回答）

证据基线：commit <sha>；测试 <命令>；架构证据 <路径>

1. 局部机制：引用 <file:function> ...
2. 边界与一致性：如果 ...
3. 线上事故：现象 ...，流量/环境 ...，如何止损、定位、修复、验证？
4. 工程权衡：比较方案 A/B ...
5. 架构演进：约束变为 ...，如何迁移、灰度、回滚并建立门禁？

请按 1-5 编号回答。每题必须引用当天的代码、测试、日志、Trace、指标或 ADR。
```

## 7. 回答和补考

- 学生关闭 Codex、Claude Code、搜索和预生成答案，每题建议 4-6 分钟。
- 回答结构：结论 -> 因果链 -> 项目证据 -> 失败模式 -> 验证 -> 取舍。
- 教师逐题指出缺失因果，不在第一次作答前给参考答案。
- 未通过时先修代码或补证据，再出五道等价但不同的问题。
- 连续两次失败，停止新功能，回到对应里程碑重做。

## 8. 学生提交格式

```text
Day N 已完成
commit: <sha>
测试输出: <路径或完整命令输出>
学习日志: <路径>

架构证据: <路径>
AI Review: accepted/modified/rejected 记录路径
```
