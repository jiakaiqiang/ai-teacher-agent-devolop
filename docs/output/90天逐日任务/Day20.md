### 3.3 第 1 关八道原理题

每题满分不等，共 30 分。作答须包含"解决什么问题 / 运行机制 / 生产误区 / 验证方法"四要素。

**题 1（4 分）reducer 为什么必须是纯函数？**
参考要点：解决"状态更新不可预测、无法单测、无法回放"；机制"相同输入必得相同输出、不改参数、无副作用"；误区"在 reducer 里发请求 / 读时间 / 改传入的 state"；验证"同一事件序列 reduce 两次结果全等、可用 fixture 回放"。

**题 2（4 分）domain 层为什么不能 import vue？**
参考要点：解决"业务逻辑绑定框架、无法在纯 Node 测试、无法迁移"；机制"domain 只依赖类型和纯函数，features 层才碰 vue 的 ref/computed"；误区"在 domain 里 import { ref } 图方便"；验证"domain 目录能在纯 Node（无 jsdom）跑测试"。

**题 3（4 分）LLM Provider 为什么要抽象接口？**
参考要点：解决"换模型要改一堆调用代码、无法 A/B 测试、供应商锁定"；机制"定义 LLMProvider 接口，OpenAI/Claude 各实现，工厂按配置注入"；误区"直接在 service 里 new OpenAI()"；验证"换 provider 只改工厂一行，业务代码不动"。

**题 4（4 分）持久化为什么要幂等键？**
参考要点：解决"webhook 重试 / 前端重复点 / 消息队列 at-least-once 导致重复 Run"；机制"业务语义字段生成稳定 key + DB 唯一约束兜底 + 应用层快速失败"；误区"用 Date.now() / 随机数做 key"；验证"同 key 请求 1000 次，DB 只有一条有效记录"。

**题 5（3 分）SSE 的 Last-Event-ID resume 解决什么？**
参考要点：解决"断线重连后丢事件 / 重复事件"；机制"客户端记 lastEventId，重连带在 header，服务端从该 sequence+1 重放"；误区"重连从 0 重放导致重复渲染"；验证"断网重连后前端不重复、不缺事件"。

**题 6（4 分）HITL 为什么审批权威必须在服务端？**
参考要点：解决"前端隐藏按钮但攻击者直接调接口 = 越权执行"；机制"批准和执行都在服务端校验角色/租户，前端只是发起 UI"；误区"前端判断 isApproved 就执行"；验证"绕过前端直接调执行接口，未批准必须 403"。

**题 7（4 分）什么是 TOCTOU 竞态？审批租约怎么防？**
参考要点：解决"批准时看到参数 A，执行时参数被换成 B / 重复提交执行两次"；机制"审批快照参数哈希 + 租约版本 + CAS 一次性消费"；误区"批准和执行之间不锁定参数"；验证"篡改参数、过期、重复提交均无副作用"。

**题 8（3 分）traceId 为什么要贯穿全链路？**
参考要点：解决"用户报'生成到一半停住'，但前端/SSE/Tool/DB 日志无法关联"；机制"入口生成 traceId，透传到每层结构化日志和 span"；误区"每层各自打日志不带 traceId"；验证"任一 Run 可按 traceId 重建完整时间线"。

### 5.2 未知 Bug 演练：竞态取消（考纲给出排查方法论，不给答案）

本次注入的 Bug（考生现场才知道现象）：**用户快速取消后，高风险 Tool 仍偶发执行，偶发率约 2%**。

这是一个典型的**跨层竞态（race condition）**。考生须独立走完四步，下面给出**方法论脚手架**（不是答案）：

**第 1 步：定位证据（10 分钟）**

- 事件回放：从 DB `agent_events` 表按 traceId（Day 18 建的）拉出这次 run 的完整事件序列
- 审批审计：查 Day 17 的 approval 审计表，看 cancel 和 tool 执行的时间戳先后
- 上游取消日志：查 Day 14 的 AbortController 传播日志，看 cancel 信号是否到达 Tool 执行层
- DB 副作用：查 Tool 实际改了哪些数据
- **关键问题**：cancel 信号发出的时刻 T1，Tool 开始执行的时刻 T2，如果 T1 < T2 但 Tool 仍执行，说明"取消信号没传到 Tool 执行的临界区"

**第 2 步：临时止损（5 分钟）**

- 禁用写 Tool（feature flag 关掉 `changeAnomalyStatus`），只读 Tool 不受影响
- 止损的代价：Agent 暂时不能执行状态变更，但不会误操作——**先保证不出错，再保证功能全**

**第 3 步：根因修复（20 分钟）**

- 竞态的根因通常是"检查取消状态"和"执行 Tool"之间存在时间窗口（TOCTOU 的变体）
- 正解方向：把"检查未取消 + 标记执行中"做成原子操作（CAS，Day 17 学过）；或在 Tool 执行的最后一刻再检查一次 abort 信号
- **考生须说明**：为什么单纯"执行前 check 一次"不够（check 完到执行之间仍有窗口）

**第 4 步：回归验证（10 分钟）**

- 偶发 2% 必须变成"能稳定复现"——用 `Promise.all` 制造 1000 次并发的"取消 + 执行"竞争，注入确定性延迟
- 修复前：约 20 次误执行；修复后：0 次
- 写成自动化回归测试进 CI

### 5.4 架构答辩的 6 个知识点（考生须能口述，每个含 5 要素）

#### 知识点 1：分层架构的依赖方向（domain/features/app 单向）

- 解决的问题：模块互相 import 导致改一处塌一片、无法单独测试
- 运行机制：domain 纯类型/纯函数（能在纯 Node 跑）、features 依赖 domain、app 编排 features；箭头单向
- 项目落点：`frontend/src/agent/reducer`（domain）不 import vue；`apps/api` 的 entity 不 import PrismaService
- 生产误区：domain 里 import 框架（Vue/Nest）；features 反向依赖 app
- 验证方法：domain 层能在纯 Node 跑测试不报错

#### 知识点 2：合同演进的向后兼容（加法变更 vs 破坏变更）

- 解决的问题：新增事件让旧客户端崩溃
- 运行机制：同一 version 内加事件是加法变更（旧客户端 default 降级）；改字段类型/删字段是破坏变更（须升 version）
- 项目落点：第 2 关的 `run.cancelled-by-policy` 加在 v1 内；default 降级不崩溃
- 生产误区：加了新事件不做 default 降级；破坏变更不升版本
- 验证方法：旧客户端收新事件的兼容测试

#### 知识点 3：Provider 抽象的代价与收益

- 解决的问题：绑死一家 LLM API，换供应商要改一片代码
- 运行机制：Day12 的 `LLMProvider` 接口 + 工厂；业务只依赖接口
- 项目落点：`apps/api/src/agent/provider/llm-provider.interface.ts`
- 生产误区：抽象过度（为不会发生的第 3 家供应商加配置）；抽象不足（接口泄漏了 OpenAI 特有字段）
- 验证方法：新增一个 mock provider 不改业务代码就能切换

#### 知识点 4：状态机的终态保护

- 解决的问题：终态后又来事件把状态改回运行中
- 运行机制：reducer 规则 B——`isTerminal(status)` 为真时直接返回原 state
- 项目落点：Day01 的 reducer 终态保护；本关新事件也走终态
- 生产误区：终态判断遗漏某个状态；忘了终态保护导致状态回退
- 验证方法：终态后喂任意事件，state 不变

#### 知识点 5：跨层竞态的原子性保证

- 解决的问题：检查和执行之间的时间窗口被并发穿越（TOCTOU）
- 运行机制：把"检查 + 标记"做成 CAS 原子操作；或执行临界区最后一刻复查 abort
- 项目落点：Day17 审批 CAS；本关竞态修复
- 生产误区：以为"执行前 check 一次"够了（check 到执行之间仍有窗口）
- 验证方法：1000 次并发竞争，误执行数为 0

#### 知识点 6：可观测性的 traceId 贯穿

- 解决的问题：分层系统出事故无法关联各层日志
- 运行机制：traceId 从入口生成，透传到 WS/Agent/Tool/SSE/DB 每一层的结构化日志
- 项目落点：Day18 的 traceId 传播 + 结构化日志
- 生产误区：某一层丢了 traceId（断链）；日志记了敏感字段
- 验证方法：任一 run 能按 traceId 重建完整时间线

### 5.5 边写边问自己
