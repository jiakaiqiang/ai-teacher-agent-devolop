建立多角色共享事实索引、关键词检索基线和 Memory 写入策略

禁止新建与主项目无关的 Demo；当天改动必须进入真实用户链路或真实平台合同。

## 原理反证与架构证据

多角色记忆生命周期图；scratchpad 泄漏、冲突事实、无关命中、越权知识库

任何 AI 生成内容都要记录接受、修改或拒绝理由。核心合同、状态机、权限、Eval 标签和最终验收由人负责。

## 时间盒

原理与源码 60 分钟；真实项目增量 210 分钟；测试/故障注入 60 分钟；架构证据、AI Review 与复盘 30 分钟。

## 通过标准

至少 20 条查询并输出 Recall@K/MRR；角色 scratchpad 不跨任务；未确认内容不入长期记忆

完成后提交 commit、测试输出、学习日志、架构证据和 AI Review 记录，先回答本文件的三道课末核心问题；项目初检通过后再进入教师五连问。

## 课末 3 个核心问题

1. 请区分共享事实索引、coordinator/executor/validator scratchpad、长期 Memory 和 RAG 语料的所有权、TTL 与召回边界；一个 Agent 的推测怎样经过确认才能成为其他角色可用事实？
2. 如果故意移除今天最关键的保护机制，线上会出现什么可观察现象？请给出最小复现、定位证据、恢复动作和一条防复发测试。
3. 请引用今天的具体代码、测试和架构证据，证明项目目标已经达到；再说明当前实现距离企业生产标准还缺什么，下一步如何演进而不破坏已有合同。

## 真实项目情境题（联网更新 2026-07-13）

> 以下是依据当前中国岗位职责和官方技术机制构造的教学模拟，不代表来源企业真实发生过相同事故。题目中的规模和指标是练习约束，不是本项目已经取得的生产数据。

1. 教学模拟：coordinator、executor、validator 共用检索缓存，validator 的失败推理 scratchpad 被下一个 executor 当成已确认事实。请按五段式给出 memory_scope、task_id、source_role、缓存和审计证据，隔离角色临时记忆，修复共享事实准入，验证跨任务攻击查询，并演进 Memory/RAG 治理。
   依据：[LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)
2. 教学模拟：coordinator 把用户一句“这次先跳过测试”写成长期偏好，后续 executor 都尝试绕过验证；另有 Prompt Injection 诱导写入虚假权限。请按五段式定位写入来源和确认人，冻结可疑记忆，修复写入确认、TTL 与安全标签，验证冲突偏好，并演进可解释长期 Store。
   依据：[OWASP LLM Top 10](https://genai.owasp.org/llm-top-10/)
知识映射：Day 68：共享事实、角色临时记忆、长期记忆、RAG 边界、写入确认与隐私。
