## v1 -> v2 -> v3 执行步骤

1. **v1 最小闭环**：暴露固定根目录的 project_search 工具。先写失败测试，再完成最短用户链路；checkpoint 是一次调用或 Run 有确定终态和 traceId。
2. **v2 关键加层**：加入输入 Schema、结果上限、超时和结构化错误。复用 v1 合同；checkpoint 是正常、边界和权限/重放测试可重复。
3. **v3 生产约束**：加入路径规范化、穿越拒绝、断连取消和审计证据。补取消、超时、审计、恢复或发布门禁；checkpoint 是故障后无静默成功、越权和重复副作用。
4. **运行命令**：在 D:\demo\ai-techer\p2-agent-workbench 执行 uv run pytest tests/day72 -q；涉及前端时再执行 pnpm --dir frontend test -- --run day72。实际命令和输出写入 evidence/day72/。

## 真实项目情境题（联网更新 2026-07-13）

> 以下是依据当前中国岗位职责和官方技术机制构造的教学模拟，不代表来源企业真实发生过相同事故。题目中的规模和指标是练习约束，不是本项目已经取得的生产数据。

1. 教学模拟：项目搜索 MCP Server 每日 20 万次调用；攻击输入 `../../secrets` 绕过字符串前缀检查，另有符号链接逃出 workspace。请按五段式给出 resolved path、调用者和文件审计证据，立即禁用危险工具，修复路径边界、验证穿越语料，并演进沙箱。
   依据：[MCP Spec 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18)

   依据：[OWASP LLM Top 10](https://genai.owasp.org/llm-top-10/)
