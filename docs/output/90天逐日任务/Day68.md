## v1 -> v2 -> v3 执行步骤

1. **v1 最小闭环**：用关键词检索 20 条标注样本。先写失败测试，再实现最短用户链路；checkpoint 是一次 Run 有确定终态和 traceId。
2. **v2 关键加层**：分离 shared facts 与 role scratchpad，并记录来源/TTL。复用 v1 合同，不复制旁路实现；checkpoint 是正常、边界和权限/重放测试可重复。
3. **v3 生产约束**：加入更正、删除、跨 Session 隔离和 Handoff 检索证据。补取消、超时、审计、恢复或发布门禁；checkpoint 是故障后没有静默成功和重复副作用。
4. **运行命令**：在 D:\demo\ai-techer\p2-agent-workbench 执行 uv run pytest tests/day68 -q；涉及前端时再执行 pnpm --dir frontend test -- --run day68。实际命令和输出写入 evidence/day68/。

## 必做测试与两个反证

- 测试范围：Recall@5 基线、过期/删除、事实更正、角色隔离和空召回；至少覆盖正常、边界、权限或并发/重放、恢复中的三类。
- 反证 1：把 scratchpad 写入共享事实后切换角色，泄漏测试必须失败。记录复现步骤、可观察信号、恢复动作和恢复后测试。
- 反证 2：删除 TTL/删除传播后重放已撤回事实，检索测试必须阻止旧事实进入 Handoff。记录复现步骤、可观察信号、恢复动作和恢复后测试。

## 真实项目情境题（联网更新 2026-07-13）

> 以下是依据当前中国岗位职责和官方技术机制构造的教学模拟，不代表来源企业真实发生过相同事故。题目中的规模和指标是练习约束，不是本项目已经取得的生产数据。

1. 教学模拟：coordinator、executor、validator 共用检索缓存，validator 的失败推理 scratchpad 被下一个 executor 当成已确认事实。请按五段式给出 memory_scope、task_id、source_role、缓存和审计证据，隔离角色临时记忆，修复共享事实准入，验证跨任务攻击查询，并演进 Memory/RAG 治理。
   依据：[LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)
2. 教学模拟：coordinator 把用户一句“这次先跳过测试”写成长期偏好，后续 executor 都尝试绕过验证；另有 Prompt Injection 诱导写入虚假权限。请按五段式定位写入来源和确认人，冻结可疑记忆，修复写入确认、TTL 与安全标签，验证冲突偏好，并演进可解释长期 Store。
   依据：[OWASP LLM Top 10](https://genai.owasp.org/llm-top-10/)
知识映射：Day 68：共享事实、角色临时记忆、长期记忆、RAG 边界、写入确认与隐私。
