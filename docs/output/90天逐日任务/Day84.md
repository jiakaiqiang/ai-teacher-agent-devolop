## v1 -> v2 -> v3 执行步骤

1. **v1 最小闭环**：复用 Day67 validator 检查 diff 和测试退出码。先写失败测试，再完成最短用户链路；checkpoint 是一次任务有确定终态、owner 和 traceId。
2. **v2 关键加层**：交叉验证命令、原始日志、changed files 和 Artifact hash。复用 v1 合同；checkpoint 是正常、边界和权限/并发测试可重复。
3. **v3 生产约束**：加入对抗样本、独立 Runtime、误报/漏报记录和证据不足终态。补预算、审计、恢复、Eval 或发布门禁；checkpoint 是故障后无静默成功、越权和重复副作用。
4. **运行命令**：在 D:\demo\ai-techer\p2-agent-workbench 执行 uv run pytest tests/day84 -q；涉及前端时再执行 pnpm --dir frontend test -- --run day84。实际命令和输出写入 evidence/day84/。

## 必做测试与两个反证

- 测试范围：真实通过、伪造测试、空 diff、缺文件、陈旧日志、权限越界和返工上限；至少覆盖正常、边界、权限或并发/重放、恢复中的三类。
- 反证 1：只信任 executor 的 passed 文本，伪造日志样本必须骗过旧版并被 v3 拒绝。记录复现步骤、可观察信号、恢复动作和恢复后测试。
- 反证 2：复用修改前的绿色日志，commit/hash 一致性测试必须识别陈旧证据。记录复现步骤、可观察信号、恢复动作和恢复后测试。
