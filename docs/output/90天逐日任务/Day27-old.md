## 真实项目情境题（联网更新 2026-07-13）

> 以下是依据当前中国岗位职责和官方技术机制构造的教学模拟，不代表来源企业真实发生过相同事故。题目中的规模和指标是练习约束，不是本项目已经取得的生产数据。

1. Message 已提交，但 Outbox 插入失败；UI 已展示内容，事件消费者永远收不到。请用事务日志、Outbox 表和消费位点定位双写裂缝；先扫描并补发缺失事件止损，再把业务写与 Outbox 放入同一事务，崩溃点注入验证无“已展示未发布”。回答必须按“定位证据 -> 临时止损 -> 根因修复 -> 回归验证”组织。
   依据：[S25 PostgreSQL isolation](https://www.postgresql.org/docs/current/transaction-iso.html)
2. 两个请求基于同一 version 更新 Diagnosis，一个静默覆盖另一个；软删除记录又被普通查询返回。请用隔离级别、版本号、SQL 和审计定位；先启用冲突告警/过滤止损，再实现乐观锁与默认 scope，100 并发更新验证冲突可见且无丢失更新。回答必须按“定位证据 -> 临时止损 -> 根因修复 -> 回归验证”组织。
   依据：[S25 PostgreSQL isolation](https://www.postgresql.org/docs/current/transaction-iso.html)
知识映射：ACID、隔离级别、乐观锁、Outbox 和软删除。
