## 一、知识点与推导

### 1.1 requestId 跨异步链，但不会自动跨队列

AsyncLocalStorage 保存当前异步执行链的上下文。D18 已在入口校验 x-request-id：8-64 位字母、数字、连字符；非法或缺失生成 UUID，响应头带回。多个并发请求不能共用普通全局变量。

BullMQ 的消费是另一条执行链，甚至是另一个进程。生产者把 requestId 放到 job.data，Worker 再调用 runWithRequestId。所有 started/completed/failed 日志都必须在这个 run 内；把 catch 放在上下文外，失败日志就可能丢掉关联。

| 标识 | 作用 | 不能替代什么 |
|---|---|---|
| requestId | 关联入口与后续工作 | 身份、权限、幂等 |
| jobId | 定位一份队列任务 | 每次尝试、永久业务唯一键 |
| attempt | 区分同任务处理尝试 | 全局唯一标识 |
| 事务事件 | 表示一次 I/O 或提交/回滚尝试 | 持久审计、整个分布式 Trace |

**推导题**：同一个任务失败后重试，requestId 应重建吗？

<details><summary>参考答案</summary>

保留原 requestId 才能回到最初受理请求，用 jobId 和 attempt 区分任务与尝试。没有上游 ID 的后台任务可生成自己的关联 ID。本章只给告警 Worker 建立完整关联，不能宣称所有维护/通知任务已贯穿。

</details>

### 1.2 JSON 只是编码，字段选择决定安全性

先核对 [Nest 官方日志文档](https://docs.nestjs.com/application/logger.md)和安装类型，再使用 ConsoleLogger 的 json、redact。它已经支持一行一个 JSON，不需要额外引入日志库。业务字段在 JSON 的 message 对象里，外层由 Nest 提供级别、时间等元信息。

固定事件：http.completed、http.database_error、http.transaction_conflict、http.unexpected_error、queue.started/completed/failed、db.transaction_io/error。允许字段只包含 method、route、statusCode、durationMs、aborted、queue、jobId、attempt、operation、errorCode。

不要传完整 req/Error，然后期待正则能擦干净。内置 redact 能按字段名遮蔽结构化属性，安装类型明确说明普通字符串、Error 的 message/stack 不在同样保护范围。本章未知异常只取受限错误码，不输出原始 message/stack；SQL 参数和任意请求体从源头不进入事件对象。

**推导题**：把 password 字段遮掉后，`message: "登录密码=..."` 安全了吗？

<details><summary>参考答案</summary>

没有，字段脱敏不会理解任意文本语义。本章业务字段白名单不接收 message/body；调用点也只给固定事件和安全元数据。白名单不代表允许字段里可以随便塞秘密，例如把 token 塞进 route 同样错误。

</details>

### 1.3 结束日志要跟着响应生命周期

普通业务拦截器可能在守卫拒绝前还没执行，SSE 返回 Observable 也不等于流已经结束。本章中间件放在 requestContext 之后，对 response 监听 finish/close，用 written 标记保证只记一次。finish 表示写出完成；close 若 writableFinished=false，记 aborted=true。

route 来自匹配模板，例如 `/api/tickets/:ticketNo`，不能用 originalUrl，因为 query 中可能有 SSE 票据；未匹配和框架兜底通配统一为 unmatched。首次测试发现 Nest 的 404 仍有通配路由，已修正该分类并保留失败历史。

耗时用 performance.now 的差值。对 SSE，这个数字是连接持续时间，不能混作普通 API 首字节或单次业务响应延迟。本章已测普通成功/401/404/500，真实流关闭与代理测试留到后续日期。

**推导题**：事务回滚以后，db.transaction_io 日志是否也该消失？

<details><summary>参考答案</summary>

日志描述实际尝试，失败尝试应保留；数据库审计描述成功业务事实，仍与业务同事务回滚。只有看到 commit 事件成功也不能推断整个异步链已成功通知用户。当前记录事务适配器 I/O，不等于数据库服务器的全部 SQL 日志。

</details>

**apps/server/src/common/structured-log.ts**

```ts
import { ConsoleLogger } from '@nestjs/common';
import { currentRequestId } from './request-context.js';

// 优先使用 Nest 内置 JSON logger；业务事件采用字段白名单，不接收完整请求或 Error。
const logger = new ConsoleLogger({
  json: true, colors: false, forceConsole: true,
  redact: ['password', 'authorization', 'cookie', 'ticket', 'accessToken', 'JWT_SECRET', 'SEED_USER_PASSWORD'],
});
const SAFE_FIELDS = new Set(['method', 'route', 'statusCode', 'durationMs', 'aborted', 'queue', 'jobId', 'attempt', 'operation', 'errorCode']);

export function eventRecord(event: string, fields: Record<string, unknown> = {}) {
  const safe: Record<string, string | number | boolean | null> = {};
  for (const [key, value] of Object.entries(fields)) {
    if (SAFE_FIELDS.has(key) && (value === null || typeof value === 'boolean' || typeof value === 'number' && Number.isFinite(value) || typeof value === 'string')) {
      safe[key] = typeof value === 'string' ? value.slice(0, 160) : value;
    }
  }
  return { event, requestId: currentRequestId() ?? null, ...safe };
}

export function logEvent(event: string, fields: Record<string, unknown> = {}, level: 'log' | 'warn' | 'error' = 'log'): void {
  logger[level](eventRecord(event, fields), 'Operations');
}

// 不读取 message/stack/查询参数。保留已知错误码用于聚类，其余统一归类。
export function safeErrorCode(error: unknown): string {
  if (error && typeof error === 'object' && 'code' in error && typeof error.code === 'string' && /^(P\d{4}|[A-Z0-9_]{2,40})$/.test(error.code)) return error.code;
  return 'UNCLASSIFIED';
}
```

import { runWithRequestId } from './request-context.js';
import { eventRecord, logEvent, safeErrorCode } from './structured-log.js';

describe('结构化日志（D37）', () => {
  it('白名单拒绝密码、票据、任意 body 和错误文本', () => {
    const record = eventRecord('probe', { statusCode: 200, password: 'fake-pass', ticket: 'fake-ticket', body: 'private-body', message: 'raw-secret', arbitrary: 'hidden' });
    expect(record).toEqual({ event: 'probe', requestId: null, statusCode: 200 });
  });

  it('并发请求的上下文在 await 后仍各自独立，结束后不残留', async () => {
    const rows = await Promise.all(['trace-aaaa', 'trace-bbbb'].map((id) => runWithRequestId(id, async () => {
      await new Promise((resolve) => setTimeout(resolve, 5));
      return eventRecord('probe');
    })));
    expect(rows.map((row) => row.requestId)).toEqual(['trace-aaaa', 'trace-bbbb']);
    expect(eventRecord('outside').requestId).toBeNull();
  });

  it('内置 logger 每条输出可独立解析，换行不会伪造新日志', () => {
    const spy = vi.spyOn(console, 'log').mockImplementation(() => {});
    try {
      runWithRequestId('trace-json-37', () => logEvent('probe', { route: 'one\ntwo' }));
      expect(spy).toHaveBeenCalledOnce();
      const line = String(spy.mock.calls[0]![0]);
      expect(line.split('\n')).toHaveLength(1);
      expect(JSON.parse(line).message).toMatchObject({ event: 'probe', requestId: 'trace-json-37', route: 'one\ntwo' });
    } finally { spy.mockRestore(); }
  });

  it('错误只暴露代码，不读取带秘密的 message 或 stack', () => {
    expect(safeErrorCode({ code: 'P2002', message: 'fake-secret' })).toBe('P2002');
    expect(safeErrorCode(new Error('fake-secret'))).toBe('UNCLASSIFIED');
    expect(safeErrorCode({ code: 'bad code with data' })).toBe('UNCLASSIFIED');
  });
});

**apps/server/src/common/request-context.ts**

```ts
import { AsyncLocalStorage } from 'node:async_hooks';
import { randomUUID } from 'node:crypto';
import type { NextFunction, Request, Response } from 'express';

// 请求上下文（D18）：同一个请求里任何地方都能拿到请求 ID，不用一层层当参数传
// AsyncLocalStorage 跟着异步调用链走：await、Promise、Prisma 的回调里都还在同一个上下文
interface RequestContext {
  requestId: string;
}

const storage = new AsyncLocalStorage<RequestContext>();

export function currentRequestId(): string | undefined {
  return storage.getStore()?.requestId;
}

// 在指定的请求 ID 下执行（D29）：后台任务没有 HTTP 请求，用入队时那个请求的 ID，审计和日志能对上最初的请求
export function runWithRequestId<T>(requestId: string, fn: () => T): T {
  return storage.run({ requestId }, fn);
}

// 客户端（或网关）传了合法的 x-request-id 就沿用，方便跨服务追踪；否则生成一个
// 只接受字母、数字和连字符：它会写进日志和审计，不能让人塞进换行之类的字符伪造日志
const VALID_REQUEST_ID = /^[A-Za-z0-9-]{8,64}$/;

export function requestContextMiddleware(req: Request, res: Response, next: NextFunction) {
  const incoming = req.header('x-request-id');
  const requestId = incoming && VALID_REQUEST_ID.test(incoming) ? incoming : randomUUID();
  // 响应头里带回去：用户报问题时给出这个 ID，就能找到对应的日志和审计
  res.setHeader('x-request-id', requestId);
  storage.run({ requestId }, next);
}
```

**apps/server/src/common/http-log.middleware.ts**

```ts
import { performance } from 'node:perf_hooks';
import type { NextFunction, Request, Response } from 'express';
import { currentRequestId, runWithRequestId } from './request-context.js';
import { logEvent } from './structured-log.js';

export function httpLogMiddleware(req: Request, res: Response, next: NextFunction) {
  const started = performance.now();
  const requestId = currentRequestId()!;
  let written = false;
  const complete = (aborted: boolean) => {
    if (written) return;
    written = true;
    // 使用匹配到的路由模板，不写 URL、query、body 或认证头；404 合并成固定名称。
    const path: unknown = req.route?.path;
    runWithRequestId(requestId, () => logEvent('http.completed', {
      method: req.method,
      route: typeof path === 'string' && !path.includes('*') ? path : 'unmatched',
      statusCode: res.statusCode,
      durationMs: Math.round((performance.now() - started) * 100) / 100,
      aborted,
    }));
  };
  res.once('finish', () => complete(false));
  res.once('close', () => complete(!res.writableFinished));
  next();
}
```
