## 1. 题库原题：长文本渲染卡顿

<details><summary>原题与原文答案</summary>

2. 在实现 AI 聊天列表时，如何处理长文本渲染导致的页面卡顿？
难度：★★
考点：性能优化、虚拟列表
答案要点：
处理长文本渲染主要通过减少 DOM 节点数量和优化渲染频率来实现，核心手段是虚拟滚动和分段渲
染。
•
虚拟滚动：只渲染可视区域内的对话气泡，通过监听滚动事件动态计算偏移量。
•
异步渲染：利用 requestAnimationFrame 或分片处理，避免大段 Markdown 一次性解析阻塞主线
程。
•
样式优化：避免在对话容器中使用过多的 CSS 复杂选择器，减少重排重绘。
•
内存管理：及时销毁不可见区域的复杂组件实例，防止内存溢出。
常见坑：
•
虚拟列表在高度动态变化（AI 逐字输出）时，滚动条抖动问题。
•
Markdown 渲染器（如 marked）解析过大文本时的同步阻塞。
追问：
•
如果对话中有大量公式（MathJax）或代码高亮，如何进一步优化？

</details>
<details><summary>补充、纠错与完整答案</summary>

先用性能记录区分网络首字慢、解析重、响应式更新多、布局与绘制重，再决定优化。长列表可以虚拟化，单条长Markdown还需拆块或缓存已完成区块；只虚拟化消息数量不必然解决单条消息成本。requestAnimationFrame负责调度，不会把重解析自动搬到工作线程。Web Worker可做纯解析，DOM仍在主线程。

本章单答纯文本、最大32Ki字符，没做高频压测，因此不凭经验虚构优化收益。先把停止、归属和终止语义做对，W8再测合批与复杂渲染。动态高度虚拟列表应处理锚点和测量，不能简单写“销毁不可见组件”就保证流畅。

**追问**：每秒更新一次可以吗？可能明显损害输出及时性。选择合批窗口需要设备、输出频率和帧耗时证据；不能套固定阈值当通用最佳方案。

</details>

## 2. 网络提炼：流式页面怎样做资源和性能管理？

<details><summary>完整答案</summary>

先限制单帧/总量，再在请求归属有效时追加；界面离开、工单或身份变化时取消并丢弃旧结果。读取器在finally释放锁，提前终止还要cancel；释放锁本身不会取消网络。timer、listener和挂起Promise也要收尾。

原文将stream:true写在TextDecoder构造示例位置不准确，应传给decode；其“流式一定恒定内存”也有前提，累计文本、未消费队列和DOM都会占用内存。本项目有32Ki输出和2MiB原始流限制，但未给整体进程内存作上界证明。每秒渲染一次的建议也需测量后决定。

```json
{"case":"paced-mock","events":5,"timersAfter":0}
```

**追问**：页面不再变化能证明timer没了？不能。D48反证删clearTimeout后，取消状态可以正常，计时器数量却仍为1。

</details>

## 3. 项目题：怎样接Vue页面生命周期？

<details><summary>完整答案</summary>

通用useAssistant只负责生成，不依赖路由。useTicketAssistant接工单getter，watch变化同步reset；onScopeDispose销毁生成模块；组件负责问题与显示。原页面加载时v-if也可能卸载组件，两条路径都要幂等。身份watch在D47，晚到结果仍用序号与token检查。

```json
{"case":"ticket-switch","text":"","aborted":true}
```

反证移除reset：

```text
 FAIL  src/composables/useTicketAssistant.spec.ts > 工单助手接线（D48） > 切工单立即清空取消且不接受迟到片段
AssertionError: expected '旧工单内容' to be '' // Object.is equality

- Expected
+ Received

+ 旧工单内容
```

依据[Vue watcher清理与时序](https://vuejs.org/guide/essentials/watchers.html)。同步watch用于低频键值，不应用于大量数组变化。

**追问**：重用组件就一定不触发卸载吗？不一定，取决于key和v-if；不要从路由形式推断资源已清理，要测试实际组件树。

</details>

## 4. 项目题：停止和失败时如何保持可用性？

<details><summary>完整答案</summary>

生成中明确状态、禁重复，停止保留部分文字与停止标签，焦点回生成按钮。截断、网络中断和自然完成分别提示；不自动重发付费POST。问题有label、原生button、错误区域和键盘操作；正文不逐字加入live区域，避免重复播报，但读屏器还需专门验证。

```json
{"case":"browser-flow","busyDisabled":true,"stoppedPartial":"这是模拟排查建议。","focusReturned":true,"complete":"这是模拟排查建议。\n1. 核对告警时间和设备状态。\n2. 对比近期变更与监控曲线。\n3. 记录证据后由人工决定下一步。","mockBadge":true}
```

**追问**：焦点返回证明完全无障碍吗？只证明该路径的焦点行为；屏幕阅读器、对比度、缩放和输入法等需要额外验收。

</details>

## 5. 项目题：模型输出为什么不能直接v-html？

<details><summary>完整答案</summary>

内容是外部文本，结构合法不代表HTML安全。Vue插值会转义HTML，本章使用插值和pre-wrap；若后续做Markdown，需明确HTML关闭/消毒及链接策略，不把解析当信任。参见[Vue安全说明](https://vuejs.org/guide/best-practices/security.html)。Prompt安全和执行工具权限是另两层，纯文本渲染不解决它们。

```json
{"case":"browser-errors","source":"Playwright接口响应夹具","scenarios":[{"scenario":"length","state":"已达到长度限制，内容不完整","escaped":true},{"scenario":"eof","state":"生成中断，保留部分内容","escaped":true},{"scenario":"timeout","state":"生成中断，保留部分内容","escaped":true}],"http503":"生成失败","hidesInternal":true}
```

这些是实际浏览器里的响应夹具，验证length/EOF/error的界面语义和HTML转义；真实上游尚缺配置。

**追问**：怎样汇报集成测试？分别说明单元、真实本机接口、浏览器真实链路、浏览器夹具及未验证项，不能只给一句“端到端全部通过”。

</details>
