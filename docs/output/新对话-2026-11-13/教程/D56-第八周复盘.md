## 一、知识点与推导

### 1.1 把回放设计成可复核实验

输入记录为{at,event}，at是与startedAt同一时钟原点的毫秒数，必须有限且单调不减。事件仍通过shared schema与Generation契约。最多8192条记录容纳4096序号及有限重投；数据来自离线合成，不能据此声称线上延迟。

**推导题：为什么拒绝时钟倒退而不排序？**

<details><summary>答案</summary>

排序会隐藏采集错误并改变原始到达顺序；回放工具应保留证据，拒绝不可解释输入。

</details>

### 1.2 状态与指标使用同一个接纳结果

applyConversationEvent返回applied/duplicate/stale/terminal。只有applied的text计字符，只有已接纳终态结算；旧身份、重复和终态迟到均计分类但不污染指标。

**推导题：正文已去重，指标还会重复吗？**

<details><summary>答案</summary>

会；若metrics直接遍历原始text事件，正文正确而字符数虚高。必须共享同一接纳决定。

</details>

### 1.3 缺失终止与输入不可变

回放结束仍busy时标记MODEL_PROTOCOL_ERROR，有正文为interrupted，无正文为error，时间取最后一条记录。每次创建独立状态，不修改输入；同输入可重复得到同结果。

**推导题：最后一帧是旧身份事件会怎样？**

<details><summary>答案</summary>

若仍未终止，离线结束时刻使用整个记录的末尾；这是回放口径，不等于真实网络超时。不能拿它替代45秒在线预算。

</details>

### 1.4 复盘围绕可观察失败

先手写12题，再跑变式；反证一让重复文本进入指标，反证二放过倒退时钟。失败后恢复并核对字节与hash。模拟面试先给状态/边界，再给证据。

**推导题：为什么周日还需要新测试？**

<details><summary>答案</summary>

变式把协议去重和指标统计组合，能暴露各模块单测都通过却口径不一致的问题。

</details>

**apps/web/src/assistant/auditReplay.ts**

```ts
import {conversationEventSchema} from '@ops-ticket/shared'
import {applyConversationEvent,createGeneration,failGeneration,isGenerating} from './generation'
import {finishMetrics,measureText,metricsView,startMetrics} from './metrics'
export interface TimedEvent {at:number;event:unknown}

// 离线练习：不发请求，不恢复在线连接；每次回放均创建独立状态。
export function auditReplay(runId:string,messageId:string,startedAt:number,records:readonly TimedEvent[]) {
  if(!Number.isFinite(startedAt)||startedAt<0||records.length>8192)throw new Error('REPLAY_BUDGET')
  const run=createGeneration(runId,messageId);const metric=startMetrics(startedAt)
  const counts={applied:0,duplicate:0,stale:0,terminal:0};let previous=startedAt
  for(const record of records) {
    if(!Number.isFinite(record.at)||record.at<previous)throw new Error('REPLAY_CLOCK')
    previous=record.at
    const event=conversationEventSchema.parse(record.event)
    const result=applyConversationEvent(run,event);counts[result]++
    // 重复、旧身份及终态迟到事件都不能污染字符数和结束时间。
    if(result==='applied') {
      if(event.type==='text')measureText(metric,event.text,record.at)
      if(!isGenerating(run))finishMetrics(metric,run.status,record.at)
    }
  }
  if(isGenerating(run)){failGeneration(run,'MODEL_PROTOCOL_ERROR');finishMetrics(metric,run.status,previous)}
  return {run,counts,metrics:metricsView(metric)}
}
```

## 五、核心面试题

1. 版本化事件为什么同时需要身份与序号？ 要点：版本决定如何解释字段，runId隔离生成尝试，messageId确定消息归属，seq约束单次尝试顺序。追问：seq能代替全局请求幂等吗？不能，它只处理当前内存流事件的重复与冲突。
2. 编辑、重生成与继续提问有何区别？ 要点：继续提问以当前叶为parent；编辑与重生成以目标旧节点的parent为parent形成兄弟分支，旧后代保留。追问：后端是否收到全分支？当前只发本次question，真实多轮上下文尚未实现。
3. abort为什么不足以防止竞态？ 要点：取消是协作式通知，已排队回调和finally仍执行。epoch、token、ticket检查保护状态，attempt持有局部timer，旧finally不清新controller。追问：怎么验证？旧请求停止后立即开始新请求，再完成旧请求，确认新请求仍可取消。
