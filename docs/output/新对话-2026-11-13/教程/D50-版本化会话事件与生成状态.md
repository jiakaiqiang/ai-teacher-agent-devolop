## 一、知识点与推导

### 1.1 四种身份边界

version标识契约版本；messageId标识某条助手消息；runId标识一次生成尝试；seq从1起标识本次事件顺序。D50定义的是界面事件，不是供应商协议。W7 meta/delta/done/error留在HTTP边界，下一章由adapter转换。未知version与额外字段由strict schema拒绝。见[Zod判别联合](https://zod.dev/api#discriminated-unions)。

**推导题：能用数组下标替代messageId吗？**

<details><summary>答案</summary>

不能。编辑分支和切换显示路径会改变数组位置，而消息身份不应随显示顺序改变。

</details>

### 1.2 先校验再提交

apply先校验形状、身份、重复指纹、终态、连续序号、首帧顺序与正文上限，再改text/status/lastSeq/seen。相同seq相同规范化内容返回duplicate，内容不同抛EVENT_CONFLICT；新seq必须等于lastSeq+1。本地拒绝事件不改变已接受状态。

**推导题：有seq就能断线续传吗？**

<details><summary>答案</summary>

不能。本章seq由前端适配，后端没有保存游标/事件日志；去重只作用于同一个内存Generation。

</details>

### 1.3 成功、停止与中断

connecting/streaming才允许更新；finish.stop完成、finish.length截断；failure有正文为interrupted，无正文为error。用户stop保留正文，后续新事件terminal；重复旧事件仍先走重复/冲突检查。状态不再用多个互相矛盾的布尔值拼凑。

**推导题：停止后相同seq不同内容如何处理？**

<details><summary>答案</summary>

冲突检查在终态前，仍抛EVENT_CONFLICT；不会修改已停止状态。调用层须捕获并保持终态。

</details>

### 1.4 有限内存的真实含义

seq最多4096、单块schema限制16384、累计正文按JS length最多32768。seen保存有限条规范化JSON用于精确重复判断；这不是恒定内存，也不是token预算。Unicode码点、UTF-16与字节数不要混用，后续卡片还要单独限制数量和字段大小。

**推导题：为何不只记lastSeq？**

<details><summary>答案</summary>

只能判旧/新，不能区分相同序号的重复与冲突。若需要所有旧事件精确判等，就需有限缓存或明确淘汰语义。

</details>

import { describe, expect, it } from 'vitest'
import { appendFileSync } from 'node:fs'
import { applyConversationEvent as apply, createGeneration, failGeneration, stopGeneration } from './generation'
const event = (seq: number, extra: object) => ({ version: 1, runId: 'run-1', messageId: 'message-1', seq, ...extra })
const start = event(1, { type: 'start', mode: 'mock' })
function begun() { const run = createGeneration('run-1', 'message-1'); apply(run, start); return run }
const report = (value: object) => { if (process.env.D50_EVIDENCE_FILE) appendFileSync(process.env.D50_EVIDENCE_FILE, JSON.stringify(value) + '\n') }
describe('版本化生成状态（D50）', () => {
  it('start文本finish形成明确终态', () => {
    const run = begun(); apply(run, event(2, { type: 'text', text: '模拟建议' })); apply(run, event(3, { type: 'finish', reason: 'stop' }))
    expect(run).toMatchObject({ text: '模拟建议', status: 'completed', lastSeq: 3 }); report({ case: 'versioned-run', status: run.status, text: run.text, lastSeq: run.lastSeq })
  })
  it('重复片段只追加一次', () => {
    const run = begun(); const piece = event(2, { type: 'text', text: '一段' }); apply(run, piece)
    expect(apply(run, piece)).toBe('duplicate'); expect(run.text).toBe('一段'); report({ case: 'duplicate-event', text: run.text, lastSeq: run.lastSeq })
  })
  it('相同序号不同内容拒绝且不改状态', () => {
    const run = begun(); apply(run, event(2, { type: 'text', text: '原文' })); const before = JSON.stringify(run)
    expect(() => apply(run, event(2, { type: 'text', text: '冲突' }))).toThrow('EVENT_CONFLICT'); expect(JSON.stringify(run)).toBe(before)
  })
  it('序号跳跃拒绝且不改状态', () => {
    const run = begun(); const before = JSON.stringify(run); expect(() => apply(run, event(3, { type: 'text', text: '漏一段' }))).toThrow('EVENT_SEQUENCE'); expect(JSON.stringify(run)).toBe(before)
  })
  it('旧run和旧message不能污染新生成', () => {
    const run = begun()
    for (const old of [{ runId: 'old' }, { messageId: 'old' }]) expect(apply(run, event(2, { type: 'text', text: '污染', ...old }))).toBe('stale')
    expect(run.text).toBe(''); expect(run.lastSeq).toBe(1)
  })
  it('未知版本和额外字段拒绝', () => {
    for (const value of [{ ...start, version: 2 }, { ...start, secret: 'fake' }]) expect(() => apply(createGeneration('run-1', 'message-1'), value)).toThrow('EVENT_CONTRACT')
  })
  it('首帧必须start', () => { expect(() => apply(createGeneration('run-1', 'message-1'), event(1, { type: 'text', text: 'x' }))).toThrow('EVENT_ORDER') })
  it('第二个start拒绝', () => { expect(() => apply(begun(), { ...start, seq: 2 })).toThrow('EVENT_ORDER') })
  it('length保持截断语义', () => { const run = begun(); apply(run, event(2, { type: 'finish', reason: 'length' })); expect(run.status).toBe('truncated') })
  it('失败按有无正文区分error和interrupted', () => {
    for (const partial of [false, true]) {
      const run = begun(); if (partial) apply(run, event(2, { type: 'text', text: '部分' }))
      apply(run, event(partial ? 3 : 2, { type: 'failure', code: 'MODEL_TIMEOUT' })); expect(run.status).toBe(partial ? 'interrupted' : 'error')
    }
  })
  it('停止后迟到文本和finish不能改变终态', () => {
    const run = begun(); apply(run, event(2, { type: 'text', text: '保留' })); stopGeneration(run)
    expect(apply(run, event(3, { type: 'text', text: '迟到' }))).toBe('terminal'); apply(run, event(4, { type: 'finish', reason: 'stop' }))
    expect(run).toMatchObject({ status: 'stopped', text: '保留', lastSeq: 2 })
  })
  it('完成后同终止重投幂等且新片段忽略', () => {
    const run = begun(); const end = event(2, { type: 'finish', reason: 'stop' }); apply(run, end); expect(apply(run, end)).toBe('duplicate')
    expect(apply(run, event(3, { type: 'text', text: '迟到' }))).toBe('terminal'); expect(run.status).toBe('completed')
  })
  it('正文和事件数量有上限', () => {
    const run = begun(); for (const seq of [2, 3]) apply(run, event(seq, { type: 'text', text: 'x'.repeat(16_384) }))
    expect(() => apply(run, event(4, { type: 'text', text: 'x' }))).toThrow('OUTPUT_LIMIT'); expect(run.text).toHaveLength(32_768)
    expect(() => apply(run, event(4097, { type: 'finish', reason: 'stop' }))).toThrow('EVENT_CONTRACT')
  })
  it('本地失败不覆盖已有终态', () => { const run = begun(); stopGeneration(run); failGeneration(run, 'NETWORK'); expect(run.status).toBe('stopped') })
})

**apps/web/src/assistant/generation.ts**

```ts
import { conversationEventSchema } from '@ops-ticket/shared'

export type GenerationStatus = 'connecting' | 'streaming' | 'completed' | 'truncated' | 'stopped' | 'interrupted' | 'error'
export interface Generation {
  runId: string
  messageId: string
  status: GenerationStatus
  mode: 'mock' | 'model' | null
  text: string
  error: string | null
  lastSeq: number
  seen: Record<number, string>
}
export class ConversationError extends Error {}
export const isGenerating = (run: Generation) => run.status === 'connecting' || run.status === 'streaming'
export function createGeneration(runId: string, messageId: string): Generation {
  return { runId, messageId, status: 'connecting', mode: null, text: '', error: null, lastSeq: 0, seen: {} }
}
export function stopGeneration(run: Generation) { if (isGenerating(run)) run.status = 'stopped' }
export function failGeneration(run: Generation, code: string) {
  if (!isGenerating(run)) return
  run.status = run.text ? 'interrupted' : 'error'; run.error = code
}

// 校验全部通过后才提交状态；重复事件去重不等于请求幂等或断线恢复。
export function applyConversationEvent(run: Generation, input: unknown): 'applied' | 'duplicate' | 'stale' | 'terminal' {
  const parsed = conversationEventSchema.safeParse(input)
  if (!parsed.success) throw new ConversationError('EVENT_CONTRACT')
  const event = parsed.data
  if (event.runId !== run.runId || event.messageId !== run.messageId) return 'stale'
  const fingerprint = JSON.stringify(event)
  if (run.seen[event.seq] !== undefined) {
    if (run.seen[event.seq] !== fingerprint) throw new ConversationError('EVENT_CONFLICT')
    return 'duplicate'
  }
  if (!isGenerating(run)) return 'terminal'
  if (event.seq !== run.lastSeq + 1) throw new ConversationError('EVENT_SEQUENCE')
  if (event.type === 'start' ? run.lastSeq !== 0 : run.mode === null) throw new ConversationError('EVENT_ORDER')
  if (event.type === 'text' && run.text.length + event.text.length > 32_768) throw new ConversationError('OUTPUT_LIMIT')
  if (event.type === 'start') run.mode = event.mode
  if (event.type === 'text') { run.text += event.text; run.status = 'streaming' }
  if (event.type === 'finish') run.status = event.reason === 'length' ? 'truncated' : 'completed'
  if (event.type === 'failure') { run.error = event.code; run.status = run.text ? 'interrupted' : 'error' }
  run.lastSeq = event.seq; run.seen[event.seq] = fingerprint
  return 'applied'
}
```

**packages/shared/src/conversation.ts**

```ts
import { z } from 'zod';

const identity = {
  version: z.literal(1),
  runId: z.string().min(1).max(64),
  messageId: z.string().min(1).max(64),
  seq: z.number().int().min(1).max(4096),
};
// 界面协议独立版本；W7的HTTP协议由前端适配，后续卡片沿用同一身份和序号。
export const conversationEventSchema = z.discriminatedUnion('type', [
  z.object({ ...identity, type: z.literal('start'), mode: z.enum(['mock', 'model']) }).strict(),
  z.object({ ...identity, type: z.literal('text'), text: z.string().max(16_384) }).strict(),
  z.object({ ...identity, type: z.literal('finish'), reason: z.enum(['stop', 'length']) }).strict(),
  z.object({ ...identity, type: z.literal('failure'), code: z.enum(['MODEL_UNAVAILABLE', 'MODEL_PROTOCOL_ERROR', 'MODEL_OUTPUT_LIMIT', 'MODEL_TIMEOUT', 'MODEL_CANCELLED']) }).strict(),
]);
export type ConversationEvent = z.infer<typeof conversationEventSchema>;
```

## 五、核心面试题

1. 为什么要同时有version、messageId、runId和seq？ 要点：版本控制解析规则，消息ID定位会话节点，生成ID隔离尝试，序号约束单次流顺序。它们不能互相替代。追问：同一问题重生成怎么办？新消息/新run，保留旧分支，后续D51实现。
2. 重复与冲突怎么区分，校验失败应改状态吗？ 要点：解析后保存规范化事件的JSON；相同seq同内容duplicate，不同内容EVENT_CONFLICT。形状、顺序、上限失败均在提交前发生，正文和lastSeq保持原值。追问：这是服务端幂等吗？只是本地事件去重，无请求重放保证。
3. 为何用户停止和错误中断必须分开？ 要点：停止是用户意图，保留部分文字但不称成功；错误中断可能网络/协议/模型故障，要让用户知道答案不完整。只有合法finish可完成，length单独截断。追问：错误在空正文时？error；非空时interrupted。
