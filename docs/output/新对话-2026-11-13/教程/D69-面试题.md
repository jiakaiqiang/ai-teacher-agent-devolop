## 一、题库原题与原文答案

复测题：《2026高德 Al agent 前端开发.pdf》第7页，一面第5题。D65从服务端权限回答，本日补齐前端交互与终态边界。

<details><summary>原文（只调整排版）</summary>

5. 什么是 Function Calling？前端在处理 Agent 的工具调用时需要注意什么？​
难度：★★★
考点：AI Agent 交互设计​
答案要点：
Function Calling 允许模型根据需求调用外部工具，前端负责展示调用过程并反馈执行结果。​
•
状态展示：需要设计专门的 UI 状态（如 思考中、正在查询地图、调用成功）。​
•
交互确认：对于敏感操作（如转账、删除），前端必须拦截并弹出确认框。
•
错误处理：当工具调用失败时，需要将错误信息反馈给模型，引导其重试或切换策略。
•
结果呈现：将工具返回的结构化数据（如 JSON）转化为可视化的图表或卡片。​
常见坑：
•
没处理好模型连续调用多个工具的串行/并行展示逻辑。​
•
工具返回数据过大，直接塞入 Context 导致 Token 溢出。​
追问：
•
如何在 UI 上优雅地展示 Agent 的思考链（CoT）？​

</details>

<details><summary>补充讲解与纠偏</summary>

模型返回工具建议，服务端执行器决定是否允许执行。前端展示实际事件，不把“思考中”当可验证推理，不展示私有思维链。高风险操作仅前端弹窗不足以保证安全，必须有服务端授权和确认协议；本章无写业务工具，也不会遇错自动重试模型。

</details>

## 二、项目与网络关联题

### 1. 如何设计工具调用卡片？

<details><summary>完整答案与追问</summary>

以调用ID关联参数、开始和返回，参数与结果采用受限纯文本；错误和未确认结果单独显示。最终成功取决于轮次持久化，不能把某个tool-result当作整轮完成。模拟模式显式标注。

</details>

### 2. 会话刷新如何避免重复执行？

<details><summary>完整答案与追问</summary>

URL保留会话ID，页面通过GET读取数据库历史；刷新按钮只执行GET，不重发POST。断线后保留片段并要求核对状态。若产品需要精确重放，应保存原requestKey并使用服务端幂等协议，不能用新键盲目重发。

</details>

### 3. 切换会话后如何防止旧结果串入？

<details><summary>完整答案与追问</summary>

取消旧controller并递增epoch；所有回调比较epoch、token、signal和disposed。路由变化清理旧状态，身份watch同步reset，卸载onScopeDispose取消；测试用不遵守signal的延迟依赖证明归属检查必要。

</details>

### 4. 停止后为什么不立即开放发送？

<details><summary>完整答案与追问</summary>

服务端可能尚未释放占用，也可能已经提交。先保留收到内容，通过GET确认activeTurnId及终态，再允许新一轮。停止不表示退款，不保证远端执行停止。

</details>

### 5. 如何验证界面可访问性？

<details><summary>完整答案与追问</summary>

标签与控件显式关联，所有操作用原生按钮和select/details，状态用role=status、错误关联表单。实际浏览器检查375px溢出与Tab焦点，停止后将焦点交回刷新按钮；这不等于完整读屏器审计。

</details>
