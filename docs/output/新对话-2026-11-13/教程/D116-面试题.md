# D116 面试题　超时重试与熔断

## 题库原题与原文答案

本地《2026京东前端面试-大模型方向.pdf》，第 8–9 页。

<details><summary>原题与答案原文</summary>

7. 你们项目里是如何处理大模型调用超时或失败的？​
难度：★★
考点：容错处理、用户体验
答案要点：
AI 接口通常响应较慢且不稳定，需要建立完善的重试、降级和反馈机制。​
•
自动重试：针对网络波动或 5xx 错误，实现指数退避算法的自动重试​
•
熔断机制：如果模型持续报错，切换到备用模型（如从 GPT-4 降级到 GPT-3.5）​
•
分段超时：不仅设置总超时，还要设置首包超时（First Token Timeout）​
•
交互反馈：明确告知用户错误原因（如 Token 超限、内容违规），并提供“重新生成”按钮​
常见坑：
•
超时时间设置过短，导致长文本生成被误杀
•
报错后没有清理当前的流连接，导致内存泄漏
追问：
•
如何在前端计算当前对话消耗的 Token 数量？​

</details>

题库提到备用模型与失败降级。工具操作可能改变状态，切换目标前必须先确认幂等身份与权限，并且所有尝试共享时间预算。



## 项目面试与自检

### 1. 两种失败可以使用同样的自动重试策略吗？

只读受预算控制可重试，写操作要先核对幂等键和持久回执。

### 2. 网络超时后怎样判断这一次是否已经写入？

按操作者、工单和请求键查回执，同键异参返回冲突。

### 3. 模型可以提交一个新的工具名来扩大权限吗？

注册表由服务端确定，未知名称和版本在执行前拒绝。
