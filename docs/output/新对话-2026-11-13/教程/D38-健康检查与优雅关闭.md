## 一、知识点与推导

### 1.1 健康状态是业务约定

live 只检查当前 HTTP 处理链还能响应。ready 决定接不接新业务。本项目数据库和队列是必要依赖；缓存允许工单核心 API 回源，但依赖缓存的限流和 SSE 签票有各自边界。因此 ready 的缓存降级不代表每项功能可用。

| 条件 | live | ready | 含义 |
|---|---:|---:|---|
| 三项正常 | 200 | 200 ok | 可接业务 |
| 数据库或队列异常 | 200 | 503 NOT_READY | 摘出流量 |
| 仅缓存异常 | 200 | 200 degraded | 核心功能可用，部分能力受影响 |
| 正在排空 | 200 | 503 NOT_READY | 不再接新业务 |

用 Terminus 汇总状态，公开响应只暴露服务类别与通用错误。异常原文可能含地址或凭据，先转换固定消息，再由统一过滤器输出。live 也不是操作系统心跳：事件循环完全卡死时它同样无法响应。框架接口见 [Terminus 官方文档](https://docs.nestjs.com/reliability/terminus.md)。

**推导题**：队列 Redis 掉线时让 live 失败并不断重启，能修好 Redis 吗？

<details><summary>参考答案</summary>

不能，可能把外部故障变成重启风暴。依赖故障主要影响 readiness；是否重启还需要区分本进程故障与外部故障。今天没有 Kubernetes 自动重启策略实测。

</details>

### 1.2 期限分两层，检查本身也有成本

探针不能无限等待。必要检查用 attempt().withTimeout(700).cacheFor(250)，并发检查共享短期结果；缓存检查用 boundedProbe 等待上限。数据库独立 pg 池 max=1，连接等待、客户端查询、数据库 statement_timeout 均为 500ms；队列 Redis 有命令和连接期限。

短缓存减少检查风暴，也带来最长约 250ms 的旧结果窗口。Terminus 的外层期限只能让检查及时结束；驱动不使用 AbortSignal 时，不应声称它取消了 I/O。独立探针成功也不能证明 Prisma 业务池没有耗尽，后续仍需池等待指标。

```typescript
// 外层决定何时回复；内层驱动期限负责限制真实操作。
() => indicators.check('database').attempt(async () => {
  try { await probes.pingDatabase(); }
  catch { throw new Error('DATABASE_NOT_READY'); }
}).withTimeout(700).cacheFor(250)
```

**推导题**：Promise.race 的超时先完成后，另一个 Promise 会消失吗？

<details><summary>参考答案</summary>

不会。它只停止当前等待，必须另有驱动期限或协作取消。本章 boundedProbe 的 finally 清定时器，race 已给迟到拒绝注册接收者，但不承诺释放任意永不完成的外部任务。

</details>

### 1.3 排空顺序围绕使用者与资源

```mermaid
flowchart LR
  A[收到关闭请求] --> B[draining 新请求503]
  B --> C[SSE reauth并complete]
  C --> H[等待在途HTTP结束]
  H --> D[等待三个Worker结束]
  D --> E[app.close等待HTTP]
  E --> F[断开Prisma和Redis]
```

现有请求先进入业务，摘流量不会撤销它。Nest 当前关闭流程先执行模块销毁，之后关闭 HTTP，再到 onApplicationShutdown。把 Prisma 提前放在 onModuleDestroy 可能让仍在工作中的请求断库。安装的 Nest BullMQ 队列生产者本身已经在 onApplicationShutdown 关闭，不能误说它会提前释放。今天先通过响应计数等待在途 HTTP 完成，再关闭 Worker 和模块，让顺序明确且可验证；同一应用重复请求关闭共用一个 Promise。

SSE 长连接若不完成，HTTP 关闭会被拖住。服务发送 reauth/server-shutdown 后 complete，客户端沿用 D34 的续签重连策略。停止中重新连接会收到 503，用户端需等待重试。BullMQ 的 close 等待在途任务但没有内置总期限，不能承诺所有情况下快速退出。[BullMQ 官方说明](https://docs.bullmq.io/guide/workers/graceful-shutdown)

**推导题**：await worker.close 前先 disconnect Prisma，为什么单纯空闲停机测试可能通过？

<details><summary>参考答案</summary>

空闲时没有任务继续查询，触发不了顺序缺陷。测试要让真实 Worker 停在业务入口，开始排空后断言依赖尚未释放，再放行查询并等待完成。HTTP 也用同样门闩验证。

</details>

**apps/server/src/health/dependency-probe.service.ts**

```ts
import { Injectable, type OnApplicationShutdown } from '@nestjs/common';
import { Redis } from 'ioredis';
import pg from 'pg';
import { RedisService } from '../redis/redis.service.js';

@Injectable()
export class DependencyProbe implements OnApplicationShutdown {
  // 健康探针单独限流到一个连接；驱动超时和数据库 statement_timeout 都有界。
  private readonly database = new pg.Pool({ connectionString: process.env.DATABASE_URL,
    max: 1, connectionTimeoutMillis: 500, query_timeout: 500, statement_timeout: 500 });
  private readonly queue = new Redis(process.env.QUEUE_REDIS_URL!, {
    commandTimeout: 500, connectTimeout: 500, maxRetriesPerRequest: 1, enableOfflineQueue: false,
  });
  constructor(private readonly cache: RedisService) {
    this.database.on('error', () => {});
    this.queue.on('error', () => {});
  }
  async pingDatabase(): Promise<void> { await this.database.query('SELECT 1'); }
  async pingQueue(): Promise<void> {
    if (await this.queue.ping() !== 'PONG') throw new Error('QUEUE_NOT_READY');
  }
  async pingCache(): Promise<void> {
    if (await this.cache.ping() !== 'PONG') throw new Error('CACHE_NOT_READY');
  }
  async onApplicationShutdown() {
    this.queue.disconnect();
    await this.database.end();
  }
}
```

**apps/server/src/health/bounded-probe.ts**

```ts
// 只限制等待时间，不声称取消底层 I/O；驱动仍须配置自己的超时。
export async function boundedProbe(work: () => Promise<void>, timeoutMs: number): Promise<void> {
  let timer: ReturnType<typeof setTimeout> | undefined;
  try {
    await Promise.race([
      Promise.resolve().then(work),
      new Promise<never>((_, reject) => { timer = setTimeout(() => reject(new Error('PROBE_TIMEOUT')), timeoutMs); }),
    ]);
  } finally { clearTimeout(timer); }
}
```

import { boundedProbe } from './bounded-probe.js';

describe('探针等待期限', () => {
  afterEach(() => { vi.useRealTimers(); });
  it('成功后清理计时器', async () => {
    vi.useFakeTimers();
    await boundedProbe(() => Promise.resolve(), 700);
    expect(vi.getTimerCount()).toBe(0);
  });
  it('保留驱动错误并清理计时器', async () => {
    vi.useFakeTimers();
    const error = new Error('simulated-driver-error');
    await expect(boundedProbe(() => Promise.reject(error), 700)).rejects.toBe(error);
    expect(vi.getTimerCount()).toBe(0);
  });
  it('到期返回失败，迟到的拒绝仍有接收者', async () => {
    vi.useFakeTimers();
    let rejectLate!: (reason: Error) => void;
    const work = new Promise<void>((_, reject) => { rejectLate = reject; });
    const assertion = expect(boundedProbe(() => work, 700)).rejects.toThrow('PROBE_TIMEOUT');
    await vi.advanceTimersByTimeAsync(700);
    await assertion;
    rejectLate(new Error('late-error'));
    await Promise.resolve();
    expect(vi.getTimerCount()).toBe(0);
  });
});

**apps/server/src/health/health.controller.ts**

```ts
import { Controller, Get, ServiceUnavailableException } from '@nestjs/common';
import { HealthCheck, HealthCheckService, HealthIndicatorService } from '@nestjs/terminus';
import { Public } from '../auth/public.decorator.js';
import { logEvent } from '../common/structured-log.js';
import { DependencyProbe } from './dependency-probe.service.js';
import { ShutdownState } from './shutdown-state.js';
import { boundedProbe } from './bounded-probe.js';

@Controller('health')
export class HealthController {
  constructor(private readonly health: HealthCheckService, private readonly indicators: HealthIndicatorService,
    private readonly probes: DependencyProbe, private readonly shutdown: ShutdownState) {}

  @Public()
  @Get('live')
  live() { return { status: 'alive' }; }

  @Public()
  @Get('ready')
  @HealthCheck()
  async ready() {
    if (this.shutdown.draining) throw new ServiceUnavailableException({ code: 'NOT_READY', message: '服务正在停止' });
    try {
      const result = await this.health.check([
        () => this.indicators.check('database').attempt(async () => {
          try { await this.probes.pingDatabase(); } catch { throw new Error('DATABASE_NOT_READY'); }
        }).withTimeout(700).cacheFor(250),
        () => this.indicators.check('queue').attempt(async () => {
          try { await this.probes.pingQueue(); } catch { throw new Error('QUEUE_NOT_READY'); }
        }).withTimeout(700).cacheFor(250),
        async () => {
          const indicator = this.indicators.check('cache');
          // 缓存降级仍能提供核心工单 API；SSE 签票等依赖缓存的功能会返回自己的 503。
          try { await boundedProbe(() => this.probes.pingCache(), 700); return indicator.up(); }
          catch { return indicator.degraded(); }
        },
      ]);
      return { status: result.status, database: result.details.database.status,
        queue: result.details.queue.status, cache: result.details.cache.status };
    } catch {
      logEvent('health.not_ready', { errorCode: 'DEPENDENCY_UNAVAILABLE' }, 'warn');
      // 对公开探针只给通用状态，不暴露连接串、堆栈或驱动细节。
      throw new ServiceUnavailableException({ code: 'NOT_READY', message: '必要依赖暂不可用' });
    }
  }
}
```

**apps/server/src/health/shutdown-state.ts**

```ts
import { Injectable } from '@nestjs/common';

@Injectable()
export class ShutdownState {
  private stopping = false;
  private active = 0;
  private readonly waiters = new Set<() => void>();
  get draining() { return this.stopping; }
  begin() { this.stopping = true; }
  trackResponse(): () => void {
    this.active++;
    let finished = false;
    return () => {
      if (finished) return;
      finished = true;
      this.active--;
      if (this.active === 0) {
        for (const resolve of this.waiters) resolve();
        this.waiters.clear();
      }
    };
  }
  waitForResponses(): Promise<void> {
    if (this.active === 0) return Promise.resolve();
    return new Promise((resolve) => { this.waiters.add(resolve); });
  }
}
```
