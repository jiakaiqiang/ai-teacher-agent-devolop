## 一、知识点与推导

### 1.1 数字必须带口径

| 指标 | 类型 | 本章口径 |
|---|---|---|
| ops_http_requests_total | Counter | 普通HTTP在finish或close时累计一次 |
| ops_http_duration_seconds | Histogram | 同一普通请求从中间件进入到结束，单位秒 |
| ops_sse_connections | Gauge | 当前进程已建立SSE连接 |
| ops_queue_jobs | Gauge | 固定三queue、waiting/active/delayed/failed快照 |
| ops_outbox_pending | Gauge | published_at IS NULL数量 |
| ops_outbox_oldest_created_timestamp_seconds | Gauge | 最早未投递事件的创建时间戳，空时0 |

Counter在进程重启时归零，不是数据库的累计业务总量。`5xx数/请求总数`必须用同一时间窗口的增量；4xx、主动断连不能自动算成服务端5xx。Histogram的桶是累计小于等于边界的数量，`_sum/_count`是平均值，不是P95。不同实例的P95不能简单求平均。

本章普通HTTP排除健康接口、metrics接口和已建立的SSE。请求未正常finish却close，标记aborted；SSE用连接Gauge单独观测。统计不含Nginx内部响应、数据库每条普通查询耗时或浏览器渲染时间。

**推导题**：一个SSE保持两分钟，能否说API响应慢两分钟？

<details><summary>答案</summary>

不能。这是连接存活期，不是首帧延迟。普通HTTP与SSE拆开；若需要SSE首帧或端到端通知延迟，另设明确的起止事件与指标。

</details>

### 1.2 维度决定成本，也决定泄露范围

```text
/api/tickets/T-a → /api/tickets/:ticketNo
/api/tickets/T-b → /api/tickets/:ticketNo
不存在的随机路径 → unmatched
```

标签仅method、route、status_class；method用有限集合，未知归OTHER。路由由匹配后的模板获取，原始URL、query、requestId、用户ID都不进入指标。每新增一个不同标签组合就新增时间序列；单个ID放进去能让内存持续增长。[Prometheus埋点建议](https://prometheus.io/docs/practices/instrumentation/)

完成回调有去重标记，因为finish之后还可能close。每个Nest应用持有自己的Registry，不使用全局默认注册器；测试并排创建应用也不会重名。

**推导题**：把requestId截短成8位，就能作为低基数标签吗？

<details><summary>答案</summary>

不能，仍随请求增长，还会碰撞。requestId用于日志关联，不是指标聚合维度。通过指标发现异常后，再按时间和接口查日志。

</details>

### 1.3 积压不是健康检查的同义词

DB和队列能连通，Outbox仍可能多年未投递。count表示规模，最早创建时间表示停滞程度。用单条SQL读取数量和min时间以保持数据库语句快照；三条Redis队列与数据库之间没有跨系统一致快照。paused、waiting-children等状态本章未统计，不把四状态之和叫“队列所有任务”。

采集失败/超过1秒返回503 METRICS_UNAVAILABLE。没有成功返回的数字就是没有本次样本，不能硬写0。超时后底层I/O可能继续；同一个应用复用尚未完成的采集，所有底层任务settle后才解除。底层永不完成时后续抓取会持续503，当前没有自动重建连接的方案。

最早时间戳便于采集系统按当前时间求年龄，但空时0必须结合pending>0判断，不能直接time()-0报警。HTTP/SSE是实例本地数据，队列/Outbox是共享资源快照，多实例抓取时不能把共享积压简单求和。

**推导题**：把数据库异常catch后返回pending:0，会怎样？

<details><summary>答案</summary>

监控会把“无法观测”当“没有积压”，故障恰好隐藏。故障状态与业务数量应分开。本章采用整个抓取503，代价是同次HTTP指标也暂时不可取得。

</details>

### 1.4 本地集成与生产承诺之间的边界

Nginx访问日志新增 `$upstream_http_x_request_id`，记录应用最终接受/生成的ID；这样客户端没传或传了非法ID时也有应用回传值。上游未响应时可能没有ID，不能据此宣称所有网关失败都可贯穿。

本机容器专项登录carol后读取通知历史；该只读接口使用事务，可同时匹配代理访问日志、http.completed和db.transaction_io。令牌与密码仅在进程内使用。完整e2e会重建测试资源，因此容器应用必须在它结束后才启动。

**推导题**：健康检查通过、容器能启动，是否证明干净生产环境一条命令可部署？

<details><summary>答案</summary>

没有。当前复用已迁移种子的隔离测试库，依赖现有Docker和缓存；生产还要配置、秘密、迁移、备份和网络。本周验证本机编排，不擅自创建生产环境或执行发布。

</details>

## 四、本章完整源码

**apps/server/src/operations/metrics.service.ts**

```ts
import { Injectable } from '@nestjs/common';
import { Counter, Histogram, Registry } from 'prom-client';
import type { NextFunction, Request, Response } from 'express';

const METHODS = new Set(['GET', 'POST', 'PUT', 'PATCH', 'DELETE', 'HEAD', 'OPTIONS']);
const EXCLUDED = new Set(['/api/operations/metrics', '/api/health', '/api/health/live', '/api/health/ready']);

@Injectable()
export class MetricsService {
  // 每个应用独立注册，测试启动多个 Nest 应用也不会重复注册到全局。
  readonly registry = new Registry();
  private readonly requests = new Counter({
    name: 'ops_http_requests_total', help: 'Completed ordinary HTTP responses or aborted connections',
    labelNames: ['method', 'route', 'status_class'] as const, registers: [this.registry],
  });
  private readonly duration = new Histogram({
    name: 'ops_http_duration_seconds', help: 'Ordinary HTTP duration until finish or close',
    labelNames: ['method', 'route', 'status_class'] as const,
    buckets: [0.01, 0.05, 0.1, 0.3, 1, 3], registers: [this.registry],
  });

  middleware() {
    return (req: Request, res: Response, next: NextFunction) => {
      const started = performance.now();
      let recorded = false;
      const complete = () => {
        if (recorded) return;
        recorded = true;
        const template: unknown = req.route?.path;
        const route = typeof template === 'string' && !template.includes('*') ? template : 'unmatched';
        // 成功建立的长连接不与普通请求耗时混算；拒绝的签票/连接仍算普通错误响应。
        if (EXCLUDED.has(route) || String(res.getHeader('content-type')).startsWith('text/event-stream')) return;
        const labels = {
          method: METHODS.has(req.method) ? req.method : 'OTHER', route,
          status_class: res.writableFinished ? `${Math.floor(res.statusCode / 100)}xx` : 'aborted',
        };
        this.requests.inc(labels);
        this.duration.observe(labels, Math.max(0, (performance.now() - started) / 1000));
      };
      res.once('finish', complete);
      res.once('close', complete);
      next();
    };
  }
}
```

**apps/server/src/operations/metrics.service.spec.ts**

```ts
import { EventEmitter } from 'node:events';
import type { Request, Response } from 'express';
import { MetricsService } from './metrics.service.js';

function response(finished: boolean) {
  return Object.assign(new EventEmitter(), { writableFinished: finished, statusCode: 200, getHeader: () => undefined });
}
describe('请求指标生命周期', () => {
  it('finish 后 close 不能重复累计，Registry 按应用隔离', async () => {
    const first = new MetricsService(); const second = new MetricsService();
    const res = response(true);
    first.middleware()({ method: 'GET', route: { path: '/api/example' } } as Request, res as unknown as Response, () => {});
    res.emit('finish'); res.emit('close');
    const text = await first.registry.metrics();
    expect(text).toContain('ops_http_requests_total{method="GET",route="/api/example",status_class="2xx"} 1');
    expect(await second.registry.metrics()).not.toContain('/api/example');
  });
  it('未完成响应单列 aborted，未知方法与未匹配路由归并', async () => {
    const metrics = new MetricsService(); const res = response(false);
    metrics.middleware()({ method: 'CUSTOM', route: { path: '/*path' } } as Request, res as unknown as Response, () => {});
    res.emit('close');
    expect(await metrics.registry.metrics()).toContain('method="OTHER",route="unmatched",status_class="aborted"');
  });
});
```
