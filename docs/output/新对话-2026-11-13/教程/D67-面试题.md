## 一、题库原题与原文答案

题库：《2026阿里云高级前端开发（AI经验）.pdf》第8页，第7题。

<details><summary>原文（只调整排版）</summary>

7. 在大模型应用中，如何处理 Token 长度限制带来的上下文丢失问题？​
难度：★★
考点：LLM 限制、状态管理​
答案要点：
由于模型窗口有限，必须采取策略在保留核心信息的同时精简上下文。
•
滑动窗口：只保留最近的 N 轮对话记录。​
•
摘要压缩：将较早的对话通过模型生成一份简短摘要，替换掉原始长文本。
•
关键信息提取：仅保留用户画像、当前任务目标等核心 Metadata。​
•
向量检索：将历史记录存入向量数据库，仅在需要时按需检索相关片段。
常见坑：
•
简单粗暴地截断文本，导致模型丢失关键的指令或前提条件。
•
忽略了 System Prompt 也占用 Token 空间。​
追问：
•
前端如何预估当前输入的 Token 数量？​

</details>

<details><summary>补充讲解与纠偏</summary>

本章没有调用模型生成摘要，也没有向量检索；只做旧问题摘录。UTF8字节预算是确定性的工程保护，不是tokenizer；生产接入要按具体模型窗口、工具schema及输出预留校准。裁剪后原始历史仍在数据库，不能把摘要替换理解成删除记录。

</details>

## 二、项目与网络关联题

### 1. 如何保证工具调用在裁剪后仍配对？

<details><summary>完整答案与追问</summary>

把一条用户问题、assistant工具批次、所有对应tool结果和最终assistant回答作为完整组；仅移出最老整组。读取时先验证ID、数量、字段和结果JSON，非法存储记录拒绝复用。

</details>

### 2. 摘要为何不能放进system？

<details><summary>完整答案与追问</summary>

它来自用户历史，可能包含恶意指令或过时事实，不具有系统权限。本项目使用user角色的结构化摘录，保留轮次来源；执行权限继续由确定性服务代码约束，不能声称这消除了所有提示注入。

</details>

### 3. 字节预算和token预算有什么差别？

<details><summary>完整答案与追问</summary>

UTF8字节是编码长度，token由模型tokenizer决定；同字节数不对应固定token数。当前预算只限制messages JSON体积，工具定义、输出和供应商包装另需预留，尚未验证具体供应商窗口。

</details>

### 4. 用户权限没变化，旧结果为何还要复核？

<details><summary>完整答案与追问</summary>

业务资源可以独立改组。只比较用户权限指纹会漏掉此变化，所以每次回显和续聊前批量检查历史引用的工单与设备仍处于当前scope，失败则保留历史但拒绝展示和继续。

</details>

### 5. 网络关联题：预算滑窗循环怎么避免无法终止？

<details><summary>完整答案与追问</summary>

改编自[上下文裁剪三策略](https://juejin.cn/post/7706364863912624170)，发布2026-11-10，已读正文和示意代码。原示意循环检查keep的预算却只删除older，无法降低被检查的长度，可能一直循环直至空数组报错。本章每次确实减少候选完整轮次并重算实际messages，最多40次；不采用零延迟、检索保真度最高等未经本项目验证的泛化结论。

</details>
