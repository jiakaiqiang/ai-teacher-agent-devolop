5. TypeScript 中的 interface 和 type 有什么区别？​
难度：★
考点：TS 基础语法​
答案要点：
两者都可以定义对象结构，但 interface 侧重于结构的声明和合并，type 侧重于类型的定义和组合。​
•
扩展方式：interface 使用 extends，type 使用交叉类型 &​
•
声明合并：同名 interface 会自动合并，同名 type 会报错​
•
能力差异：type 可以定义基本类型别名、联合类型、元组，interface 不行​
•
适用场景：定义公共 API 建议用 interface，定义复杂逻辑或联合类型用 type​
常见坑：
•
试图在 type 中使用 implements 关键字​
•
忽略了 interface 无法描述非对象类型​
追问：
•
什么是泛型？在 AI 接口请求中如何使用泛型约束返回结果？​

</details>

## 二、项目与网络关联题

### 1. 类型注解、mypy与运行时校验分别负责什么？

<details><summary>完整答案与追问</summary>

注解描述程序约定，mypy在运行前检查可分析的调用与赋值，解析器检查真实值。三者互补。Any会让错误绕过部分检查；object迫使使用前先缩小类型。

</details>

### 2. Protocol为什么适合替换批处理worker？

<details><summary>完整答案与追问</summary>

调用方依赖可调用对象的参数与返回类型，无需继承某个具体实现。后续可注入测试函数。Protocol默认不运行时检查签名和返回数据，即使runtime_checkable也不能当完整输入验证。

</details>

### 3. 为什么检查未知字段和条数上限？

<details><summary>完整答案与追问</summary>

未知字段需要明确版本与兼容策略；本练习选择严格拒绝。条数与长度预算限制单次工作量，但只保护已解析对象的结构，不能替代HTTP请求字节上限或鉴权。

</details>

### 4. 网络关联：有了mypy还要验证JSON吗？

<details><summary>完整答案与追问</summary>

根据2026-11-05[类型注解关联文章](https://juejin.cn/post/7704241004282609698)改编。mypy不会把注解变成运行时检查；接口需显式解析。本文用bool反例说明仅看表面类型还不够。文章关于未注解函数的表述需结合配置：strict会要求注解，检查范围也由files确定。依据：[typing官方文档](https://docs.python.org/3.12/library/typing.html)。

</details>
