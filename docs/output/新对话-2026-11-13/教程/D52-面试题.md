## 一、题库原题与原文答案

题库：《2026MiNiMax前端AI开发.pdf》第2页，长文本渲染题。

<details><summary>原文（只调整排版）</summary>

2. 在实现 AI 聊天列表时，如何处理长文本渲染导致的页面卡顿？
难度：★★
考点：性能优化、虚拟列表
答案要点：
处理长文本渲染主要通过减少 DOM 节点数量和优化渲染频率来实现，核心手段是虚拟滚动和分段渲
染。
•
虚拟滚动：只渲染可视区域内的对话气泡，通过监听滚动事件动态计算偏移量。
•
异步渲染：利用 requestAnimationFrame 或分片处理，避免大段 Markdown 一次性解析阻塞主线
程。
•
样式优化：避免在对话容器中使用过多的 CSS 复杂选择器，减少重排重绘。
•
内存管理：及时销毁不可见区域的复杂组件实例，防止内存溢出。
常见坑：
•
虚拟列表在高度动态变化（AI 逐字输出）时，滚动条抖动问题。
•
Markdown 渲染器（如 marked）解析过大文本时的同步阻塞。
追问：
•
如果对话中有大量公式（MathJax）或代码高亮，如何进一步优化？

</details>

<details><summary>补充讲解与纠偏</summary>

原答案把rAF与异步分片并列，需区分：rAF只安排在帧回调中运行，同步parse仍阻塞主线程。本章用帧合批和有界输入降低重复工作，未测量性能改善百分比。虚拟列表只能减少挂载节点，不能解决单条超长Markdown解析成本。

</details>

## 二、项目与网络关联题

### 1. 如何安全地展示模型返回的Markdown？

<details><summary>完整答案与追问</summary>

将模型输出视为不可信文本。关闭原始HTML，token白名单转Vue VNode，仅文本子节点承载内容，属性只手动允许安全href与固定target/rel；图片退成说明，不加载远程资源。追问：解析库升级后还安全么？需复核token API与安全测试，不能因为当前通过就永久信任插件。

</details>

### 2. 未闭合代码块是否需要先补三个反引号？

<details><summary>完整答案与追问</summary>

不需要，本实现按CommonMark把围栏延伸到当前文档末尾，代码内容保持文本；原文不改写。围栏长度和标记种类均有语义，简单奇偶计数错误。追问：四反引号里的三反引号？仍是代码内容，测试已覆盖。

</details>

### 3. rAF合批与真正增量解析差别是什么？

<details><summary>完整答案与追问</summary>

合批减少调用频次，仍对有界累计全文解析。增量解析要维护语法状态和依赖关系，处理后来引用定义改变前文等问题。追问：为什么不冻结所有空行前内容？不能证明那些块语义永远不受后文影响。

</details>

### 4. 网络题：Markdown流式解析如何避免标签截断，全量重渲染行不行？

<details><summary>完整答案与追问</summary>

题目来源[Markdown流式解析面试题](https://juejin.cn/post/7682217734722027558)，发布2026-09-07，已读正文。答案：先明确预览策略，再控制解析/渲染频率与内容安全。文章的空行冻结和标记奇偶计数只是简化思路，无法完整覆盖CommonMark；未闭合fence本就可按代码解析，不必等闭合才显示。本章选择有界全量重解析、VNode更新、rAF合批，保留语义正确性；仍可能有格式变化，不宣称完全无闪烁。追问：长文再如何做？测量后选worker/真正增量parser或受限语法，不未经证据冻结前文。

</details>

### 5. 为什么既要源码长度限制，又要节点数量限制？

<details><summary>完整答案与追问</summary>

相同长度可以生成一个文本节点，也可生成大量短段/强调节点。两个预算控制不同资源；超限保留受限纯文本，避免整页崩溃。追问：能否证明永不阻塞？不能，预算减少风险，低配设备和实际帧耗时尚需浏览器测量。

</details>
