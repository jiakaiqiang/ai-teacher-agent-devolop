## 一、知识点与推导

### 1.1 动态高度前缀与窗口

layoutRows按稳定ID读取高度Map，无测量时估180px，前缀offsets[i]是第i行顶部。rowAt二分查所属行，visibleRange追加上下overscan。DOM只挂载窗口行，外层高度保留滚动空间。当前会话最多200节点，重算前缀O(n)，不为教学容量提前引入树结构。

**推导题：为什么scrollTop/固定行高不够？**

<details><summary>答案</summary>

Markdown换行、代码和卡片让行高不同；流式期间同一行仍增长。固定除法会定位到错误消息。

</details>

### 1.2 跟随意图与阅读锚点

底部距离48px内可跟随；用户向上滚轮立即暂停，scroll处理键盘/触摸/拖动滚动条。内容更新通过ResizeObserver收集测量，每帧统一提交。暂停时先保存anchor={id,offset}，更新高度后按新前缀恢复；跟随时去新底部。程序写scrollTop记expected，避免自身scroll事件被误当用户意图。

**推导题：为何只比较旧scrollTop不够？**

<details><summary>答案</summary>

上方高度改变后，同一scrollTop对应不同文字；应保存当前阅读消息和行内偏移。用户在await nextTick期间继续滚动时，不再用旧锚点强行覆盖。

</details>

### 1.3 DOM测量与Vue生命周期

测量用borderBoxSize或getBoundingClientRect，包含row内边距；外层overflow-anchor:none让手动锚点策略单独生效。onUpdated观察新挂载行，移出行unobserve，卸载disconnect并取消rAF。容器宽度变化清旧高度估算，随后重新测当前窗口。依据[ResizeObserver规范](https://drafts.csswg.org/resize-observer/)。

**推导题：测完高度就能同步设置最终scrollTop吗？**

<details><summary>答案</summary>

Vue还没提交新占位高度时，浏览器会按旧scrollHeight夹值；先更新响应式布局，再nextTick后定位。

</details>

### 1.4 键盘与辅助阅读的取舍

获得焦点的行即使离开窗口也保留，避免Tab焦点被卸载；使用稳定key、region名称、list/listitem与posinset/setsize。显示全部开关提供本页浏览器查找与辅助阅读路径，最多200节点。没有真读屏器验证，不能宣称符合完整无障碍标准。

**推导题：虚拟化能解决一条32768单元长消息吗？**

<details><summary>答案</summary>

该消息仍整体渲染，虚拟化只减少消息数量；单消息parse和DOM复杂度由D52预算控制。

</details>

**apps/web/src/assistant/virtual.ts**

```ts
export interface Layout { ids: string[]; offsets: number[]; total: number }
export function layoutRows(ids: string[], heights: ReadonlyMap<string, number>, estimate = 180): Layout {
  const offsets = [0]
  for (const id of ids) offsets.push(offsets[offsets.length-1]! + Math.max(1, heights.get(id) ?? estimate))
  return { ids, offsets, total: offsets[offsets.length-1]! }
}
export function rowAt(layout: Layout, position: number) {
  let low=0; let high=layout.ids.length
  while(low<high) { const mid=(low+high)>>>1; if(layout.offsets[mid+1]! <= position) low=mid+1; else high=mid }
  return Math.min(low,Math.max(0,layout.ids.length-1))
}
export function visibleRange(layout: Layout, top: number, viewport: number, overscan = 2) {
  if (!layout.ids.length) return { start:0,end:0 }
  return { start:Math.max(0,rowAt(layout,Math.max(0,top))-overscan),end:Math.min(layout.ids.length,rowAt(layout,Math.max(0,top)+viewport)+1+overscan) }
}
export function anchorAt(layout: Layout, top: number) {
  const index=rowAt(layout,top); return { id:layout.ids[index] ?? '', offset:top-layout.offsets[index]! }
}
export function restoreAnchor(layout: Layout, anchor: {id:string;offset:number}) {
  const index=layout.ids.indexOf(anchor.id)
  return index < 0 ? 0 : layout.offsets[index]! + Math.min(Math.max(0,anchor.offset),layout.offsets[index+1]!-layout.offsets[index]!-1)
}
export const nearBottom = (top:number,viewport:number,total:number) => total - top - viewport <= 48
```

const props=defineProps<{items:T[]}>()

let pending:number|undefined;let disposed=false;let expected:number|undefined;let userRevision=0;let width=0;let resetHeights=false
const measurements=new Map<string,number>();const observed=new Set<Element>()
function scrollTo(position:number) {
  const el=viewport.value;if(!el)return
  expected=Math.max(0,Math.min(position,layout.value.total-el.clientHeight));el.scrollTop=expected;top.value=el.scrollTop
}
function onScroll() {
  const el=viewport.value;if(!el)return;top.value=el.scrollTop
  if(expected!==undefined && Math.abs(el.scrollTop-expected)<2) {expected=undefined;return}
  expected=undefined;userRevision++;following.value=nearBottom(el.scrollTop,el.clientHeight,el.scrollHeight)
}
function queueLayout() {
  if(pending!==undefined || disposed)return
  pending=requestAnimationFrame(async()=>{
    pending=undefined;if(disposed)return
    const anchor=anchorAt(layout.value,viewport.value?.scrollTop ?? top.value);const userAtStart=userRevision

    for(const [id,value] of measurements) heights.set(id,value)
    measurements.clear();revision.value++;await nextTick();if(disposed)return
    if(following.value)scrollTo(layout.value.total)
    else if(userAtStart===userRevision)scrollTo(restoreAnchor(layout.value,anchor))
  })
}
function observeRows() {

  for(const row of observed) if(!current.has(row)){rowObserver?.unobserve(row);observed.delete(row)}

}

  const ids=new Set(props.items.map(item=>item.id));for(const id of heights.keys())if(!ids.has(id))heights.delete(id)
  queueLayout()
},{flush:'post'})
watch(all,queueLayout,{flush:'post'})
onMounted(()=>{

    for(const entry of entries){const id=(entry.target as HTMLElement).dataset.virtualRow!;const value=entry.borderBoxSize[0]?.blockSize ?? (entry.target as HTMLElement).getBoundingClientRect().height;if(Math.abs((heights.get(id)??180)-value)>.5)measurements.set(id,value)}
    if(measurements.size)queueLayout()
  })

  })

})

## 五、核心面试题

1. 动态高度虚拟列表如何找可见范围？ 要点：稳定ID保存测量高度，未知估算；累计前缀提供每行位置，二分找视口起止并加overscan，外层维持总高度。追问：更新复杂度？当前O(n)重算、O(log n)查询，200行有界；大规模且频繁测量再考虑Fenwick tree等。
2. 用户向上读旧消息时新内容到达怎么办？ 要点：暂停跟随，记录消息ID和行内偏移。高度变化后恢复对应位置，底部新增不能强拉用户；回到最新按钮恢复跟随。追问：为什么scrollTop数值没变仍会跳？上方行高度改变导致数值对应的内容变了。
3. 虚拟化对键盘与读屏器有什么影响？ 要点：卸载焦点节点会丢焦点，未挂载消息不能被原生查找完整检索；保留focus行与全部显示开关，提供list语义和位置总数。追问：有ARIA就证明可访问吗？不，仍需读屏器/键盘实际验收；本章模型测试不能代替D55浏览器。
