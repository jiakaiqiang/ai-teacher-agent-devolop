# D51面试题：会话分支与停止重生成

配套[D51讲义](D51-会话分支与停止重生成.md)。先口述2分钟，再展开答案。题库文件名不表示企业官方背书。

## 一、题库原题与原文答案

题库：《2026MiNiMax前端AI开发.pdf》第6—7页，多轮中断与重生成题。本章复用同一原题，但重点从生成状态转向会话分支。

<details><summary>原文（只调整排版）</summary>

5. 如何实现一个支持“多轮对话中断”和“重新生成”的状态机？
难度：★★★
考点：逻辑设计、状态机
答案要点：


通过定义明确的状态（Idle, Generating, Paused, Error）和 Action 来管理复杂的对话流。
•
中止逻辑：利用 AbortController 关联 Fetch 请求，在用户点击“停止”时触发 abort()。
•
覆盖更新：重新生成时，需定位到当前消息 ID，清空后续内容并重新触发流式请求。
•
历史回溯：支持修改历史提问，此时需要截断后续对话树，发起新的分支请求。
•
幂等性：确保多次点击重新生成不会导致状态错乱。
常见坑：
•
请求已 abort 但前端状态未重置，导致 UI 卡死。
•
重新生成时未处理好 Token 消耗的统计。

</details>

<details><summary>补充讲解与纠偏</summary>

原答案的覆盖/截断策略会丢失旧分支，本章按保留记录要求选择只切换活动路径；不存在删除接口。暂停不等于续传，重新生成是新请求，可能产生新的模型费用。刷新和离开工单会释放本页内存，尚无持久历史承诺。

</details>

## 二、项目与网络关联题

### 1. 编辑和重生成如何保留旧记录？

<details><summary>完整答案与追问</summary>

每次新建turn和run，parentId等于被替换节点的父节点。旧节点、其后代和回答保持；activeLeaf指向新节点。选回旧后代能恢复原路径。追问：为何不slice原数组？数组是全部分支存储，slice会丢历史；只对展示路径做选择。

</details>

### 2. 怎么防止旧finally影响新请求？

<details><summary>完整答案与追问</summary>

捕获epoch/token/ticket并在callback/catch/finally共同检查current。旧任务允许自然settle，但不得清新timer/controller/currentRun。stop先标终态，再失效并abort。追问：token相同就足够吗？同一用户连续两次生成仍会竞态，所以还要epoch。

</details>

### 3. 多轮界面等于模型有上下文吗？

<details><summary>完整答案与追问</summary>

不等于。这里transport只发送当前问题，树只用于界面与分支回看。真正上下文选择、截断和预算属于后端协议设计，不能在产品文案声称已记住前文。追问：seq能检测HTTP漏包吗？本地adapter只编号已收到的合法应用事件，不能凭空知道遗漏。

</details>

### 4. 网络关联题：如何让不合作的异步请求不再卡住界面？

<details><summary>完整答案与追问</summary>

改编自[异步并发控制](https://juejin.cn/post/7678670603645747250)，2026-08-28，已读正文。本章用abort promise与transport竞争，45秒期限触发受控超时；清除timer和listener，旧结果检查归属。原文fetch.finally清超时只覆盖响应头阶段，流体读取仍可能悬挂，应把预算覆盖到终止。追问：race会让底层自动消失吗？不会，需abort并理解底层合作程度。

</details>

### 5. 为何容量超限要拒绝，而不是自动删除前面的记录？

<details><summary>完整答案与追问</summary>

本轮要求保留历史；前端内存需有上限，二者可以通过拒绝新请求兼容。200节点和100万UTF-16正文/问题预算包含非活动分支，并为下一回答预留32768。追问：真实内存就是100万个字符吗？不是，指纹、对象、Vue响应式与渲染都额外占用；这里只限制内容容量。

</details>
