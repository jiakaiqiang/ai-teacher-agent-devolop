### 1.1 先界定三种时钟

从客户端发起请求到首个完整 SSE 帧叫首帧时间。总时间持续到 EOF 或异常。proxy_read_timeout 约束 Nginx 两次读取上游之间的空闲时间，持续有数据的连接可以活得更久。

### 1.2 缓冲与帧边界

proxy_buffering off 让上游数据尽快转发，proxy_cache off 关闭缓存。客户端按空行识别完整帧，不能把一次 reader.read 当作一条事件。仅开启缓冲的初次实验没有观测到首帧堆积，这次尝试保留在历史日志中。

**可运行示例：首帧堆积到末尾被发现**

来源：`apps/server/src/retrieval/proxy-timing.spec.ts`。输入、预期结果和断言如下；完整夹具见第四节。

```ts
it('首帧堆积到末尾被发现', () => {

});
```

在`apps/server`运行：

```powershell

```

<details><summary>答案</summary>

</details>

### 1.3 HTTP成功后还可能失败

200响应头可以先于上游故障到达。超时中断以后，客户端可能只拿到部分正文并在读取阶段抛错。应用需要独立终态和错误提示。


**apps/server/src/retrieval/proxy-timing.ts**

```ts
// 只比较完整 SSE 帧到达的相对时间；块数量不等于事件数量。
export function assessProxy(firstMs: number, totalMs: number, frames: number) {
  if (![firstMs,totalMs].every(Number.isFinite) || firstMs<0 || firstMs>totalMs) throw Error('BAD_CLOCK');
  if (frames!==6) throw Error('INCOMPLETE_STREAM');
  if (firstMs>=1500) throw Error('BUFFERED_FIRST_EVENT');
  if (totalMs<3000) throw Error('EARLY_END');
  return { firstMs,totalMs,frames };
}
```

```text
    server_name localhost;
    access_log off;
    location / {
        proxy_pass http://fixture:3000;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 2s;
        proxy_connect_timeout 2s;
    }
}
```

**infra/stream-fixture.mjs**

```text
import { createServer } from 'node:http';
// 仅用于专属本机代理实验，不接受业务数据。
createServer((req,res) => {
  res.writeHead(200,{'Content-Type':'text/event-stream','Cache-Control':'no-store'});
  res.write('data: first\n\n');
  if (req.url === '/idle') return;
  let n=0;
  const tick=setInterval(()=>{
    n++;
    res.write('data: '+n+'\n\n');
    if (n===5) { clearInterval(tick); res.end(); }
  },700);
  res.on('close',()=>clearInterval(tick));
}).listen(3000,'0.0.0.0');
```
