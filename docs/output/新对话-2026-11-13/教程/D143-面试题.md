<details><summary>原题与答案原文</summary>

9. 如何处理大模型对话中的上下文管理（Context Window）？​
难度：★★★
考点：AI 业务逻辑​
答案要点：
由于模型有上下文长度限制，前端需要策略性地管理发送给后端的历史消息。
•
滑动窗口：仅保留最近的 N 条对话记录。​
•
摘要压缩：将较早的对话通过 LLM 生成简短摘要，替换原始长文本。​
•
Token 预算控制：在前端计算 Token，当接近阈值时提醒用户或自动截断。​
•
关键信息保留：保留 System Prompt 和最近几轮对话，中间部分进行剔除。​
常见坑：


•
简单截断导致模型丢失关键的前置设定。
•
频繁生成摘要增加额外的 API 开销。​
追问：
•
如何判断哪些消息是“关键”的，不应该被删除？
•
向量数据库在长短期记忆管理中起到什么作用？

</details>

短期历史与跨会话设置有不同来源。本节在渲染交接时显式查后者，删除后下一次不用它。
