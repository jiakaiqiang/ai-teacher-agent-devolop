3. 如何设计 Prompt 以保证稳定的 JSON 格式？​
•
明确约束：在 System Prompt 中加入 Response in valid JSON format only 。​
•
Few-shot：给出 1-2 个具体的输入输出 JSON 示例。​
•
Schema 定义：提供 JSON Schema 描述字段含义。​
•
防御编程：前端对返回内容进行正则截取（提取 {...} 之间的内容）并配合 try-catch 。​

</details>

<details><summary>补充讲解与纠偏</summary>

System提示和few-shot只能影响生成，不保证JSON有效，更不保证事实正确。不要用贪婪正则从任意文本中截取花括号再当可靠结果；本项目下一章严格解析完整content并验证schema，失败最多修复一次。

</details>

## 二、项目与网络关联题

### 1. Prompt版本与业务代码版本为什么要对应？

<details><summary>完整答案与追问</summary>

提示改变字段解释和不确定性表达，会影响用户行为。记录明确版本、保留旧文本和对应测试；涉及结构契约变化还需同步schema与消费者。

</details>

### 2. 模板hash不含用户输入有什么好处和局限？

<details><summary>完整答案与追问</summary>

便于检查模板而不泄露业务材料；同模板不同请求hash相同，因此不是请求ID、输入指纹或完整回放证据。

</details>

### 3. JSON材料中的role字段会成为system消息吗？

<details><summary>完整答案与追问</summary>

正常JSON序列化不会把字符串拆成消息对象；代码固定两个role。模型仍能阅读字符串中的指令，所以语义注入风险不能仅靠序列化消失。

</details>

### 4. 如何评估新模板是否更好？

<details><summary>完整答案与追问</summary>

固定有代表性的样本和评分标准，对版本做同条件评估，记录模型/参数/schema与人工核验。先跑结构回归，再看分类、优先级、缺失信息与幻觉；本章未做真实效果A/B。

</details>

### 5. 网络关联题：集中管理Prompt还缺什么？

<details><summary>完整答案与追问</summary>

改编自[我把Prompt当代码管：前端prompt版本化方案](https://juejin.cn/post/7651406306646868003)，发布2026-06-15，正文已读，非企业原题。文章建议版本并存、集中选择和回归清单。本项目把提示放服务端，未知变量拒绝而不默默替换空串；确定性结构可以严格断言，模型质量另用样本和人工评估，不能因生成随机就放弃自动化验证。

</details>
