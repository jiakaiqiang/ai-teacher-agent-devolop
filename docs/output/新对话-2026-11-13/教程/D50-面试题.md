# D50面试题：版本化会话事件与生成状态

配套[D50讲义](D50-版本化会话事件与生成状态.md)。先口述2分钟，再展开答案。题库文件名不表示企业官方背书。

## 一、题库原题与原文答案

题库：《2026MiNiMax前端AI开发.pdf》第6—7页，多轮中断与重新生成题。

<details><summary>原文（只调整排版）</summary>

5. 如何实现一个支持“多轮对话中断”和“重新生成”的状态机？
难度：★★★
考点：逻辑设计、状态机
答案要点：


通过定义明确的状态（Idle, Generating, Paused, Error）和 Action 来管理复杂的对话流。
•
中止逻辑：利用 AbortController 关联 Fetch 请求，在用户点击“停止”时触发 abort()。
•
覆盖更新：重新生成时，需定位到当前消息 ID，清空后续内容并重新触发流式请求。
•
历史回溯：支持修改历史提问，此时需要截断后续对话树，发起新的分支请求。
•
幂等性：确保多次点击重新生成不会导致状态错乱。
常见坑：
•
请求已 abort 但前端状态未重置，导致 UI 卡死。
•
重新生成时未处理好 Token 消耗的统计。

</details>

<details><summary>补充讲解与纠偏</summary>

原答案给出Idle/Generating/Paused/Error的方向，但Paused不能直接表示可恢复；当前协议只能新发请求。覆盖更新/截断历史也不是唯一做法：本周采用保留旧分支。多次点击互斥与请求幂等不同，runId负责结果归属，无法证明供应商不重复计费。

</details>

## 二、项目与网络关联题

### 1. 为什么要同时有version、messageId、runId和seq？

<details><summary>完整答案与追问</summary>

版本控制解析规则，消息ID定位会话节点，生成ID隔离尝试，序号约束单次流顺序。它们不能互相替代。追问：同一问题重生成怎么办？新消息/新run，保留旧分支，后续D51实现。

</details>

### 2. 重复与冲突怎么区分，校验失败应改状态吗？

<details><summary>完整答案与追问</summary>

解析后保存规范化事件的JSON；相同seq同内容duplicate，不同内容EVENT_CONFLICT。形状、顺序、上限失败均在提交前发生，正文和lastSeq保持原值。追问：这是服务端幂等吗？只是本地事件去重，无请求重放保证。

</details>

### 3. 为何用户停止和错误中断必须分开？

<details><summary>完整答案与追问</summary>

停止是用户意图，保留部分文字但不称成功；错误中断可能网络/协议/模型故障，要让用户知道答案不完整。只有合法finish可完成，length单独截断。追问：错误在空正文时？error；非空时interrupted。

</details>

### 4. 网络关联题：取消旧请求足以消除竞态吗？

<details><summary>完整答案与追问</summary>

改编自[异步并发控制与竞态防护](https://juejin.cn/post/7678670603645747250)，发布2026-08-28，已读正文。取消降低本机资源占用，身份门禁阻止排队旧结果写回，两者组合。原文把取消必然节省服务端token说得过满，供应商必须合作且账单需单独核验。这里已用旧run/message用例与反证证明前端隔离，不证明远端停止计费。追问：finally也要检查吗？要，否则旧请求会清掉新请求busy。

</details>

### 5. 事件预算和文本预算分别防什么？

<details><summary>完整答案与追问</summary>

文本预算限制累计正文；事件预算限制空片段/重复登记等控制状态。schema字段长度与JSON开销也需有界。D50重复返回前不增加seen；本地总正文用UTF-16单元，不冒充模型tokens。追问：为什么不宣称恒定内存？累计正文与指纹随已接受输入增长，只是有明确上限。

</details>
