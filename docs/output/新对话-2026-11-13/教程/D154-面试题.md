<details><summary>原题与答案原文</summary>

6. 谈谈你对前端团队协作和 Code Review 的看法。​
难度：★★
考点：团队协作、软技能
答案要点：
良好的协作机制是高质量交付的保证，Code Review 是知识传递和质量把控的重要手段。​
•
CR 目的：发现潜在 Bug、统一代码风格、促进团队成员间的技术交流。​
•
协作流程：明确的 PR 流程、完善的文档沉淀（RFC/技术方案设计）。​
•
沟通技巧：CR 时对事不对人，给出建设性意见而非单纯的批评。​
•
自动化辅助：利用工具自动检查基础规范，让人类专注于逻辑和架构审查。
常见坑：
•
把 CR 变成一种形式主义，或者变成权力斗争的工具。​
•
缺乏明确的文档导致沟通成本极高。

</details>

评审这个 Skill 时应对照实际允许的工具、错误码和可验证字段；描述变更还需重新核对客户端契约。



## 项目面试与自检

### 1. 更换传输后哪些校验必须保留？

当前主体、工具范围和资源复查由服务端执行，传输只影响连接与消息交付。

### 2. 两个客户端都显示“成功”能证明读到同一条记录吗？

核对真实工具回执、工单号、事件版本和拒绝场景，记录是否使用模型夹具。

### 3. 资源没有出现在列表就足够安全吗？

发现与逐项读取均核对权限，缓存键包含可见范围和版本。
