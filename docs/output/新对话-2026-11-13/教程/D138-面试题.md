# D138 面试题　稳定前缀与脱敏回放

## 题库原题与原文答案

<details><summary>原题与答案原文</summary>

7. 解释一下 HTTP 缓存策略（强缓存与协商缓存）。​
难度：★★
考点：网络协议、性能优化
答案要点：
HTTP 缓存通过减少重复请求来提升加载速度，分为强缓存和协商缓存两个阶段。​
•
强缓存：通过 Cache-Control（max-age）或 Expires 判断，命中则不发请求直接用本地资源。​
•
协商缓存：强缓存失效后，携带 ETag 或 Last-Modified 询问服务器，返回 304 则继续使用本地缓
存。
•
优先级：Cache-Control 优先级高于 Expires，ETag 优先级高于 Last-Modified。​
•
存储位置：memory cache（内存）或 disk cache（磁盘）。​
常见坑：
•
误以为 304 状态码不消耗网络带宽（实际上有一次 Header 交互）。​
•
忽略了 no-cache 和 no-store 的区别。​
追问：
•
为什么 ETag 比 Last-Modified 更可靠？​
•

</details>

浏览器缓存有 HTTP 层的协商语义。模型服务的前缀缓存按其自身规则计量，普通哈希只能校验输入是否相同。



## 项目面试与自检

### 1. 相同前缀是否意味着相同用户材料可以共享？

前缀只含通用约束。工单材料按本次主体和权限加载。

### 2. 有了引用 ID 就能读取正文吗？

引用只用于定位，读取时重新核对工单可见范围、版本及页长。

### 3. 按字符截断可能丢掉哪类事实？

按模型编码计算，优先保存证据、未解决原因及引用标识。
