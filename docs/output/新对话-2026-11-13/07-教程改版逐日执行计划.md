## 用同一组业务用例对照教程与实现

用两家客户、一名客户管理员和普通用户各一组、一个运维部门负责人、两名内部处理人构造固定样例。增加第二个运维部门验证路由，使用合成日志。每行同时核对操作者、页面动作、接口结果和持久化记录。

| 业务用例 | 预期表现 | 首次教学与后续复验 |
|---|---|---|
| 注册与数据权限 | 运维公司发放客户管理员账号。客户管理员审批本公司注册并查看本公司工单。跨公司详情和日志不可见，客户管理员无法派单、复核、发布知识或代用户验收 | D15–D20，D65、D121、D150 |
| 提交与路由 | 已获批用户主动提单。超时重提只建一张。问题分类决定承办部门。模型判断与分类冲突时仍按用户选择路由。告警可以作为日志材料 | D08、D11、D29、D62 |
| Agent 无法处理 | 显示“人工接入”。点击前没有负责人派单待办；点击后携带日志、建议和已尝试步骤，同单产生一次待办 | D08、D30–D34、D55、D111 |
| Agent 已给建议 | 提单人点“已解决”即可完成，点“未解决”直接转到对应负责人，无需再点一次接入；迟到的诊断结果不能覆盖人工状态 | D08、D13、D48、D62、D146 |
| 人工处理与返工 | 负责人只能指派内部处理人。处理人提交后为“已处理”，负责人通过后为“已复核”。用户点“未解决”回原处理人，再次提交给负责人复核。只有提单人确认才进入“已完成” | D08、D16–D20、D34、D146 |
| 成功方案发布 | 用户确认解决后生成可审核的通用草稿，工单已完成。运维部门负责人审核后按批准版本发布。乙公司可检索通用步骤，无法据此查看甲公司原工单或原始日志 | D74–D76、D82、D123–D125、D157 |
| 审核未通过或中断 | 退回的草稿不能进入共享检索；批准后篡改、重复投递或服务重启都不能造成错误版本发布 | D74、D124、D129–D132、D160 |

沿用 06 的两条设计建议，实施时在讲义注明其性质：人工结果未通过负责人复核时退回原处理人；Agent 直接解决的工单按问题分类确定知识审核负责人。D131 中的教学接收器用于跨进程可靠性实验，演示权限只属于明确授权的内部操作人，客户提单不会触发设备重启。

## 每天如何改完并交接

1. 从当天旧讲义抄录原学习目标、学员要手写的部分、原反证和预计耗时。把新案例写在旁边，给出一个能区分“会做功能”和“掌握原理”的结果。例如 D11 由并发请求及响应丢失验证幂等，D124 由批准后更改参数验证审批快照。若需要未来周次的能力，先使用带说明的固定样例。
2. 从上一天新版完成状态开始，在验证工程复用现有模块。建模从 `apps/server/prisma`、`packages/shared` 起步，业务主要涉及 `apps/server/src/tickets`、`auth`、`queue`、`notifications`，AI 部分涉及 `assistant`、`retrieval`、`agent`、`mcp`，再同步 Web 页和 Python 桥接。验证工程位置及每日快照约定见[原交接说明](05-交接给Codex.md)。
3. 运行对应单元、接口或集成用例，按原教程生成协议检查构建与 lint。当天新增一项能暴露错误的反证，或沿用原来有效的反证。涉及 UI 用页面真实入口，涉及数据库并发用真实测试库，涉及模型分别记载模拟结果和真实模型结果。恢复实验改动后再验证。
4. 按现有结构改写讲义与配套面试题。保留原理推导、三级提示、学员手写、自检、三道核心题和个人建议。章末代码从当天新版验证工程生成。面试原题和来源按原规则核对，项目解释用新版行为。题干涉及旧告警、旧班组或旧关单时，区分来源原文与项目示例。保留工作日两小时及周末集成复盘，普通表单和布局放参考实现。
5. 核对下一天的起点、前置章节、1/3/7 天回忆题、周末集成和复盘。改标题时同步引用、阅读入口和已有源码清单。按现有约定检查代码块、折叠区、链接、占位符和源码一致性。[讲义格式](02-教程格式约定.md) · [现有生成与验证步骤](00-教程生成计划.md)
6. 在 00 的新版记录填写“日号｜原知识点｜改后练习｜改动的讲义/面试题｜新版快照或源码清单｜正例、反例及结果｜未验证项｜下一日依赖”。旧验收数据归旧版。编者验证与学员提交成绩分别记录。若发现知识目标遗漏、规则冲突或课时过载，修正最早引入问题的章节，再检查实际引用它的后续章节。
