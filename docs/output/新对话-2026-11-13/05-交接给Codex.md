## 七、踩过的坑（都实际遇到过）

1. **PowerShell 里含中文弯引号（“”）的字符串会解析失败**，整条命令不执行。含中文的文件内容一律用文件写入/编辑工具，不要放进 PowerShell 的字符串里。
2. **`gen_source_generic.py` 写出的文件是 CRLF**（Python 在 Windows 上的文本模式）。之后用正则或替换时要考虑 `\r\n`。
3. **用 tsx 运行导入 NestJS 源码的脚本，请求全部 500**：esbuild 不生成装饰器元数据。要在脚本里启动 Nest 应用，先 `pnpm build`，导入 `dist`。
4. **并发测试先预热连接池**（`Promise.all` 跑 4 个 `SELECT 1`），否则第二个查询新建连接慢十几毫秒，并发根本没发生，反证实验会“意外通过”。
5. **接单上限 5 张**（D9）：测试里不断改派、接单给同一个人，很快 409。用例之间取消之前的处理中工单，或者换人。
6. **BullMQ 的连接不能设 `enableOfflineQueue: false`**：初始化时的版本检查会失败，所有请求都失败。入队的超时用 `addWithTimeout`。
7. **BullMQ 自定义任务 ID 不能含冒号、不能是纯数字**；ID 相同的任务存在时 `add` 不会再加（失败的任务会挡住重新推送）。
8. **查任务状态要先 `getJobState` 再 `getJob`**，反过来会读到“已完成但没有结果”。
9. **后端不直接依赖 zod**：测试里要用的 schema 放进 shared。
10. **`async` 辅助函数后面不能直接接 `.expect`**；没 `await` 住的请求会在后台跑，把数据漏到下一个用例。
11. **队列 Redis 连不上时 `app.close()` 会卡住**（超过 60 秒），只在故障实验里出现。
12. **并行的工具调用执行顺序不确定**：有先后依赖的操作（改文件再构建、迁移再生成）分开执行。
13. **测试数据要清理**：压测插入的 20 万张工单必须在 `finally` 里删；调试时不要用 `process.exit()`。
14. 计划第六节“已知问题”还有更早的坑（Prisma 版本、端口占用、`[IO.File]` 相对路径等），动手前看一遍。
