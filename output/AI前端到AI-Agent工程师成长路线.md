# AI 前端 -> AI 全栈 -> AI Agent 工程师成长路线

## 1. 目标与当前起点

职业目标顺序：

1. AI 前端工程师
2. AI 全栈工程师
3. AI Agent 工程师

这个顺序符合当前能力结构。已有约 7 年 Vue、企业应用、工程化、性能、低代码和工具开发经验，可以直接作为 AI 前端底座；后端刚起步，因此不能跳过 AI 全栈阶段直接把多 Agent 项目包装成 Agent 工程能力。

当前准备度：

| 目标 | 当前准备度 | 可求职门槛 | 差距 |
|---|---:|---:|---|
| AI 前端工程师 | 50/100 | 70/100 | 流式 UI、RAG/工具展示、安全、评测 |
| AI 全栈工程师 | 32/100 | 70/100 | API、数据、鉴权、部署、观测、AI 服务链路 |
| AI Agent 工程师 | 30/100 | 75/100 | Agent 循环、工具协议、工作流、评测、安全、生产治理 |

## 2. 第一阶段：AI 前端工程师

### 定位

不是“会调用聊天接口的前端”，而是能够稳定交付 AI 产品交互、处理流式状态、展示证据和工具过程、控制性能与安全的前端工程师。

### 必修能力

1. AI 交互协议
   - SSE、WebSocket、Fetch `ReadableStream` 的选型。
   - `TextDecoder(stream: true)`、半包、跨 chunk 缓冲、断线、取消、重试和幂等。
2. AI UI 状态
   - `idle/thinking/streaming/tool_call/success/error/cancelled` 状态机。
   - 会话、消息、附件、工具调用、引用和错误的结构化数据模型。
3. 流式渲染
   - Markdown、代码块、公式、增量更新节流、尾消息局部渲染。
   - 长会话虚拟列表、自动滚底与用户阅读冲突、内存清理。
4. AI 产品可信度
   - RAG 引用、证据片段、低置信度提示、重新生成、反馈。
   - 不展示私有 Chain of Thought，只展示可审计的阶段和工具摘要。
5. 安全与质量
   - Markdown/HTML 消毒、URL 协议白名单、CSP、文件上传限制。
   - 流式解析测试、错误状态测试、E2E 和性能监控。
6. 前端基础补强
   - JavaScript 异步、浏览器事件循环、HTTP、TypeScript、测试和性能。
   - 保留 Vue 优势，同时能够读懂主流 React/Hooks 代码，避免岗位面过窄。

### 阶段项目

完成一个“企业知识与任务助手”：

- 流式对话、停止生成、重试和错误恢复。
- Markdown/代码渲染、文件上传、长会话管理。
- RAG 引用与证据展示。
- 至少一个工具调用，并展示参数确认、执行状态和结果摘要。
- 记录 TTFT、完成耗时、错误率、中断率和前端渲染耗时。
- 覆盖断网、半包、未闭合代码块、重复事件、XSS 输出和超长会话测试。

### 毕业标准

- 不看答案独立实现流式解析和取消。
- 能解释 SSE 与 WebSocket 的选择和限制。
- 作品可部署、可演示、有 README、测试和性能数据。
- AI 前端专项面试达到 70/100，才能把求职标签改为“AI 前端工程师”。

## 3. 第二阶段：AI 全栈工程师

### 进入条件

先通过 AI 前端阶段。后端学习不能只靠 AI 生成代码；必须能够独立判断接口、数据、安全和部署是否正确。

### 必修能力

1. 服务端基础
   - Node.js 服务、路由、中间件、参数校验、统一异常和日志。
   - REST API、流式响应、文件上传、任务状态查询。
2. 数据与缓存
   - 关系型数据库设计、索引、事务、迁移。
   - Redis 缓存、会话、限流和幂等键。
3. 身份与权限
   - 登录、Token/Session、RBAC、资源级权限、租户隔离。
   - 前端菜单权限不能替代后端鉴权。
4. AI 服务链路
   - 模型适配器、Prompt 版本、Token/成本控制、超时重试。
   - RAG 摄取、切分、Embedding、召回、重排、引用。
   - 客户端断开时取消上游模型请求。
5. 异步任务与交付
   - 队列、任务状态、重试、死信与幂等。
   - Docker、配置与密钥、CI/CD、部署、监控和回滚。
6. 可观测性
   - 请求日志、Trace、模型/Prompt/知识库版本、延迟、错误和成本。

### 阶段项目

将第一阶段项目升级为“多租户 AI 知识平台”：

- 用户、组织、知识库和会话的服务端数据模型。
- 登录、RBAC、资源级权限和审计日志。
- 文档异步解析、向量索引和 RAG 引用。
- 模型路由、流式代理、超时、重试、限流和成本记录。
- Docker 部署、数据库迁移、自动化测试、监控和回滚说明。

### 毕业标准

- 能脱离 AI 工具独立解释每个后端模块的机制与边界。
- 能从零部署，处理一次数据迁移和一次模拟线上故障。
- 能证明鉴权、事务、幂等、日志、测试和回滚。
- 全栈专项评审达到 70/100，才能使用“AI 全栈工程师”标签。

## 4. 第三阶段：AI Agent 工程师

### 进入条件

已具备 AI 全栈交付能力。Agent 不是多个 Prompt 串起来，也不是启动多个模型进程；它是受约束、可观测、可评测的任务执行系统。

### 必修能力

1. Agent 核心循环
   - 模型决策 -> 工具调用 -> 参数校验 -> 执行 -> 结果回填 -> 继续/终止。
   - Plan/Action/Observe、状态机、步数/Token/时间预算。
2. 工具与协议
   - Tool Schema、Function Calling、MCP、工具注册与版本。
   - 权限、白名单、参数校验、幂等、人工确认和审计。
3. 工作流与多 Agent
   - DAG、条件分支、并行、重试、补偿和检查点。
   - 角色边界、上下文隔离、共享产物、冲突解决和最终验收。
4. 记忆与上下文
   - 短期状态、长期记忆、摘要、检索和上下文预算。
   - 数据权限、过期策略和隐私边界。
5. 评测与观测
   - 离线任务集、任务成功率、工具成功率、人工修改率、缺陷率。
   - Trace、重放、模型/Prompt/工具版本和成本。
6. 安全与可靠性
   - Prompt Injection、敏感操作确认、沙箱、命令白名单、密钥隔离。
   - 循环终止、降级、失败恢复和人工接管。

### 阶段项目

把当前多 Agent 协同开发成“可评测的软件任务执行平台”：

- 规划、实现、测试和审查角色有清晰输入输出契约。
- 支持任务依赖、并行、检查点、冲突检测和失败恢复。
- 代码修改以 patch/diff 交付，在沙箱运行 lint/test。
- 高风险命令需人工确认，所有工具调用可审计。
- 用同一任务集比较人工、单 Agent、多 Agent 的完成率、耗时、缺陷和成本。

### 毕业标准

- 多 Agent 相比单 Agent 的收益有数据，而不是主观感受。
- 能复现失败、查看 Trace、重放步骤并定位责任环节。
- 工具权限、预算、终止、沙箱和人工接管完整。
- Agent 系统专项评审达到 75/100，才能使用“AI Agent 工程师”标签。

## 5. 推荐节奏

时间只作为参考，以毕业标准为准：

| 阶段 | 建议周期 | 核心结果 |
|---|---:|---|
| AI 前端 | 3-4 个月 | 一个可部署、可测试、可量化的 AI 前端作品 |
| AI 全栈 | 6-9 个月 | 一个具备数据、权限、RAG、部署和观测的完整平台 |
| AI Agent | 9-18 个月 | 一个安全、可评测、可追踪的 Agent/多 Agent 系统 |

三个周期可以有重叠，但头衔不能提前。多 Agent 项目可以现在继续做，只是在后端和评测能力成熟前，把它定义为“探索项目”。

### 第二阶段毕业后

## 7. 严格原则

- Codex、Claude Code 是研发工具，不是能力等级证明。
- 完成 Demo 不等于生产交付；必须有测试、安全、观测和故障恢复。
- 会调用模型不等于 AI 前端；会写 Node.js 接口不等于 AI 全栈；会启动多个 Agent 不等于 Agent 工程师。
- 每次升级标签都以可运行项目、可解释机制、可复核数据和现场问答为准。
