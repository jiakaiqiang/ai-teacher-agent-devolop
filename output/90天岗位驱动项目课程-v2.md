# 90 天岗位驱动项目课程 v2

版本：2026-07-13  
周期：2026-07-14 至 2026-10-11  
学习强度：工作日 180 分钟，周末 360 分钟  
主线：AI 前端 -> AI 应用全栈 -> Agent 应用/平台工程  
真实项目：Day 1-60 使用 `D:\demo\ai-techer\p1-monitor`；Day 61-90 从零构建 `D:\demo\ai-techer\p2-agent-workbench`，范围见[《项目边界》](./p2-agent-workbench项目边界.md)。

## Goal

- Day 20：以高级前端视角交付可审计、可恢复、可观测的 Agent UI，不停留在聊天框。
- Day 40：补齐 Node/NestJS、SQL、鉴权、Redis、队列和全链路可靠性，达到偏前端 AI 全栈入门线。
- Day 60：独立打通 Vue、NestJS、FastAPI、RAG、Eval、部署和监控，形成可投递作品。
- Day 90：从零交付规模受控的 Agent Runtime、MCP、Context、Memory、Workflow、多 Agent、Eval 和 Trace 主链路。
- 每天都留下代码、测试、架构证据、失败实验和 AI Review 记录；功能完成但原理或独立排障不过关，当天不通过。

## Assumptions / constraints

- 已有约 7 年 Vue、工程化、低代码、ECharts/Three.js 和平台项目经验；会使用 Codex/Claude Code，但 AI Coding 尚缺量化证据。
- 后端刚起步，因此 Day 21、41、61 设置桥接日，不把工具生成的后端代码当作掌握。
- 前 60 天使用 Vue 3 + TypeScript。React/Next.js 是杭州岗位覆盖风险，不在本阶段强行插入；Day 59 依据真实投递决定是否在 Day 60 后增加迁移支线。
- 不创建互不相关的 Demo。每天只给真实项目增加一个纵向能力。
- `12.pdf` 只用于能力判断，不在课程文件传播个人联系方式等隐私信息。

- `12.pdf` 可复用能力：Vue 迁移、运维平台、权限、可视化、低代码、组件/插件、性能优化、智能助手和报表模型接入。

## Analysis

### Decision

采用“两段项目主线、六个阶段门禁、十三周迭代”的方案。先在 `p1-monitor` 把高级前端经验迁移到 AI 应用并补齐 Node/Python 后端，再从零构建规模受控的 Agent 工作台。学习顺序由数据与状态合同逐步扩展到分布式可靠性，避免先堆框架名词。

### Risks / edge cases

- React/Next.js 缺口会缩小杭州投递面；Day 59 用真实岗位矩阵决定是否加 12-15 小时迁移支线。
- Day 61 创建新的轻量项目，不读取、复制或修改现有大型多 Agent 平台；先建立合同、测试和最小可运行基线。
- 资源 PDF 对 Python、MCP、Eval、Chaos 覆盖不足；课程保留这些岗位必需能力，但在题目中明确“近似题/资源缺口”。
- 未来代码路径依赖前一天真实实现。下面固定能力、分钟和代码落点；每天领取任务时再读取实际分支，给出不会与代码冲突的 starter code。

## 每日任务必须包含的代码和步骤

每日分发文件必须在读取当天真实分支后给出以下内容，缺一项不得开工：

1. 精确文件路径和允许修改范围。
2. 一个只包含合同、TODO 和失败测试的 starter code；不能直接给最终答案。
3. 3-7 个按依赖排序的实现步骤，每步说明输入、输出和 checkpoint。
4. 可复制的运行命令和预期信号；不得伪造测试输出或性能数字。
5. 正常、边界、并发/重放、权限和恢复测试中至少三类。
6. 人工必须完成的核心合同/状态机/权限/Eval 判断，以及允许 Codex/Claude Code 完成的机械工作。

静态计划不预写 Day 2-90 的完整实现代码，因为代码路径会被前一天的真实设计改变。学生发送 `开始 Day N` 时，教师必须读取上一日 commit 和当前源码，生成当天可直接实现的代码骨架；这不是减少细节，而是防止未来教案与真实项目分叉。

## 课末问题与完成后五连问

- 每份 Day 文件结尾固定列出 3 个课末核心题：机制因果、项目反证、证据与生产差距。
- 每份 Day 文件再列出至少 2 个联网来源的真实项目情境题：给出规模/故障现象，并要求定位、止损、修复、验证；来源与边界见[《联网调研与真实项目题来源》](./联网调研与真实项目题来源-2026-07-13.md)。
- 本地 PDF 的 2 道题继续保留在最后并标来源页码；它们不替代核心题。
- 学生提交 commit、测试、日志和架构证据后，教师再提出 5 道逐层升级的问题：局部机制 -> 边界/并发 -> 线上定位 -> 工程权衡 -> 架构演进。
- 五连问必须引用学生当天真实 diff/测试/日志，不提前给固定答案；具体协议见[《AI 教师五连问验收协议》](./AI教师五连问验收协议.md)。
