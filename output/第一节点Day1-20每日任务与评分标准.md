# 第一节点 Day 1-20 高级前端架构视角项目任务与评分标准

对应总计划：`90天AI全栈与Agent工程师计划-2026-07-14.md`  
执行周期：2026-07-14 至 2026-08-02  
唯一项目：`D:\demo\ai-techer\p1-monitor`  
阶段目标：完成“指标采集 -> 实时推送 -> 异常检测 -> Agent 诊断 -> 前端时间线”的真实纵向闭环。

全程遵循[《高级前端架构视角教学总纲》](./高级前端架构视角教学总纲.md)：每天从领域、边界、合同、状态、失败和演进角度完成一个架构证据，不把高级前端等同于复杂组件或设计模式堆叠。

## 1. 不是教程路线，而是项目路线

第一阶段不创建互不相关的小项目，不以“看完课程”或“写过 Demo”作为完成标准。20 天只持续开发智能异常监控平台，每个知识点必须同时留下三类证据：

1. **原理证据**：先预测系统行为，画数据流或状态图，并能口述为什么这样设计。
2. **代码证据**：原理必须进入 `p1-monitor` 的生产代码，解决当天真实业务问题。
3. **反证证据**：通过测试或故障注入证明错误方案会怎样失败，正确方案为什么有效。

例如，学习 Event Loop 不是单独写 Promise 练习，而是解决“四类指标并发加载、取消旧请求、避免旧响应覆盖新状态”；学习 WebSocket 不是做聊天室，而是把 `metric.created` 推送到监控大盘并处理重连补偿。

## 2. 项目现状与范围决定

### 已有能力

- NestJS 11、Prisma、PostgreSQL、Jest 工程已经存在。
- `MetricsService` 每 5 秒生成 CPU、内存、温度、磁盘 IO，并发出 `metric.created`。
- `AnomalyDetectorService` 已有静态阈值、连续上升和突变检测雏形。
- Prisma 已设计 Server、Metric、Anomaly、Diagnosis、Message、ToolCall 等模型。

### 当前缺口

- 没有 Vue 前端、WebSocket Gateway、Agent Service、Tool Registry 和诊断时间线。
- 异常查询、状态流转、诊断事件协议和真实 AI 流尚未完成。
- 当前代码存在模块依赖、`any`、查询顺序、重复异常和输入校验等需要用测试验证的问题。
- 旧 PRD 中的 `maxSteps` 等框架写法可能过时，实施时以锁定版本的官方 API 为准。

### 本阶段只做的产品范围

- P0：实时监控大盘、异常检测、异常列表/详情、单 Agent 诊断、工具调用时间线。
- 暂缓：Chat 浮层、RAG、附件、多模态、完整 JWT、配置中心和多 Agent。这些进入后续节点。
- 前端使用 Vue 3 + TypeScript，不使用 React。

## 4. 每日固定学习动作

- 学生发送 `开始 Day N` 后，教师按照[《每日任务分发协议》](./每日任务分发协议.md)，结合 `12.pdf`、项目代码和上一日成绩直接分发当天任务，不进行课前提问。
- Day 2-20 的知识、项目增量、架构证据和量化门禁以[《Day 2-90 项目驱动任务总纲》](./Day02-90项目驱动任务总纲.md)为权威基线；本文件负责展开时间盒和第一节点考试。
- 开始前：关闭 AI，用 10 分钟写“我认为今天链路如何工作、最可能在哪里失败”。
- 原理学习：只阅读与当天项目问题直接相关的官方文档、源码或现有项目文档。
- 编码前：先写接口合同、状态图或失败测试，再让 Codex/Claude Code参与。
- AI 参与后：逐块审查 diff，标出接受、修改和拒绝的建议及原因。
- 结束前：运行真实检查，提交代码，进行 3 分钟无稿口述。

每日必须提交：

- 一个 `day-XX: <项目增量>` Git commit。
- `docs/learning/day-XX.md`，包含原理、设计、失败实验和复盘。
- 测试/构建/性能命令的真实输出。
- 一个可以从前一天版本升级得到的项目增量，不接受新建独立示例目录。
- 一个与当天真实代码对应的架构证据，并说明采用方案、备选方案、验证方式和重审条件。

项目任务初步验收后，必须执行[《AI 教师五连问验收协议》](./AI教师五连问验收协议.md)：从局部机制逐步追问到架构演进。五问合计至少 21/30 且每题至少 4/6，才算当天最终通过；具体题目依据真实 diff 现场生成，不提前公布。

## 5. Day 1-20 具体任务

### Day 1：07-14，3 小时，AI 前端架构与 Agent 事件模型

- 原理 30 分钟：理解 Model/BFF/Transport/Vue 边界、Agent 事件合同、状态机、Tool Calling UI 和浏览器信任边界。
- 设计 25 分钟：独立定义八类 Agent 事件、Run 状态、sequence 规则和敏感字段限制。
- AI 辅助 40 分钟：由一个 Builder 创建 Vue/Vitest/ESLint 工程骨架，人审查全部配置。
- 核心编码 45 分钟：人工实现纯 reducer 和至少 8 个状态转换测试。
- 项目 UI 25 分钟：实现可展示 text/tool/approval/error/finish 的 AgentRunPanel。
- 验证 15 分钟：AI Reviewer 只读审查，人完成 lint/typecheck/test/build 和取舍记录。
- 当日产出：AI 前端四层边界图、Agent 事件模型、状态机、Tool UI 骨架和 AI Review 证据。
- 不通过条件：使用 `data: any`、只做聊天框、把 API key 放前端、无法解释状态转换或完全由 AI 生成核心 reducer。

### Day 2：07-15，3 小时，建立领域合同而不是先画页面

- 原理 40 分钟：理解 TypeScript 静态类型、网络运行时数据和 Prisma 数据模型的边界。
- 项目 90 分钟：为 Server、Metric、Anomaly、Diagnosis、ToolCall 建立前端领域类型和运行时 Schema；定义 API 成功/错误合同。
- 反证 30 分钟：用缺字段、错误枚举、BigInt id 和非法时间戳验证“只写 interface”为什么不能保护运行时。
- 口述 20 分钟：解释 DTO、领域模型、ViewModel 为什么不应完全共用一个类型。
- 当日产出：`src/domain`、`src/api/contracts` 和合同测试。
- 不通过条件：出现 `data: any`，或未经校验就把接口 JSON 写入 Pinia。

### Day 3：07-16，3 小时，用异步原理完成指标首屏

- 原理 35 分钟：Event Loop、Promise 并发、AbortController、竞态和过期响应。
- 项目 100 分钟：封装 API Client，并发读取同一服务器四类最近指标；切换服务器时取消旧请求；展示 loading/empty/error/ready。
- 反证 25 分钟：人为延迟旧请求，证明没有 request id/取消时旧数据会覆盖新服务器。
- 复盘 20 分钟：说明为什么这里需要并发、哪些错误可重试、为什么不能无限重试。
- 当日产出：真实调用 `/metrics/recent/:serverId` 的指标 Store 和页面骨架。
- 不通过条件：用静态数组伪装接口成功，或切换服务器后出现数据串台。

### Day 4：07-17，3 小时，把时序数据变成可维护的大盘

- 原理 35 分钟：Vue 响应式更新、组件生命周期、ECharts 更新成本、滑动窗口和稳定 key。
- 项目 100 分钟：完成 CPU、内存、温度、磁盘 IO 四图；统一单位、时间排序、空值和异常点样式；只保留最近 60 点。
- 反证 30 分钟：比较全量重建图表与增量更新的渲染次数和内存变化。
- 复盘 15 分钟：记录选择 60 点窗口的业务依据和未来扩展条件。
- 当日产出：使用真实数据库指标的监控大盘，不创建 ECharts 示例页。
- 不通过条件：组件卸载后仍有 chart/listener，或指标顺序错误导致曲线倒序。

### Day 5：07-18，6 小时，打通真实 WebSocket 指标链路

- 原理 60 分钟：比较轮询、SSE、WebSocket；理解握手、连接生命周期、背压和广播范围。
- 后端 120 分钟：新增 WebSocket Gateway，监听现有 `metric.created` 并发布类型化 `metrics` 事件；加入连接日志和基础测试。
- 前端 120 分钟：接入 socket.io-client，把实时事件合并到 Day 4 的 Store 和滑动窗口。
- 反证 40 分钟：模拟重复、乱序、非法和高频事件，验证合同校验与 sequence 处理。

### Day 6：07-19，6 小时，让实时链路能断线恢复

- 原理 60 分钟：至少一次投递、重复事件、心跳、指数退避、jitter、快照补偿和幂等。
- 项目 150 分钟：实现连接状态机、心跳、指数退避重连、sequence 去重；重连后通过 REST 快照补齐缺失窗口。
- 故障注入 90 分钟：依次停止后端、断网、重复推送、乱序推送、后台标签页 10 分钟，再恢复。
- 性能 40 分钟：持续运行并记录事件延迟、重连时间、内存和渲染长任务，不预写漂亮数字。
- 复盘 20 分钟：说明 WebSocket 为什么不能天然保证业务“恰好一次”。
- 当日产出：断线可见、自动恢复、数据不重复的 M1。
- 不通过条件：重连后静默丢数据，或连接恢复时重复注册 listener。

### Day 7：07-20，3 小时，用测试修正异常检测链路

### Day 13：07-26，6 小时，持久化 Agent 执行而不是只打印结果

### Day 17：07-30，3 小时，高风险工具必须人工确认

- 当日产出：真实改变异常状态且可审计的 Human-in-the-loop 闭环。
- 不通过条件：模型能直接执行状态变更，或批准请求可重复生效。

### Day 18：07-31，3 小时，建立可观测性和性能基线

- 原理 35 分钟：Trace、结构化日志、TTFT、P95、错误率、长任务和内存泄漏。
- 项目 85 分钟：request/trace id 贯穿 WebSocket、异常、Agent、ToolCall、SSE 和前端日志；记录 TTFT、诊断耗时、工具成功率。
- 性能 40 分钟：运行 10 台设备、四类指标和连续诊断，记录延迟、帧率、内存及慢点。
- 安全 20 分钟：抽查日志，确认 API key、Authorization、消息原文和敏感参数未泄漏。
- 当日产出：基于真实运行数据的性能与可观测性报告。
- 不通过条件：只写目标数值，没有测量方法、原始数据和复现步骤。

### Day 19：08-01，6 小时，全链路故障演练与发布候选

- 计划 40 分钟：冻结功能，列出核心用户旅程、故障矩阵和回滚条件。
- E2E 140 分钟：覆盖指标产生、实时推送、异常检测、Agent 工具调用、诊断展示和人工批准的完整链路。
- 故障注入 100 分钟：模型 429/超时、数据库慢查询、WebSocket 断开、SSE 断流、重复事件、工具失败和浏览器刷新。
- 修复 50 分钟：只修复阻塞性问题，重新执行全量测试和构建。
- 证据 30 分钟：录制 8 分钟无剪辑项目演示，必须包含一次失败、定位和恢复。
- 当日产出：M4 发布候选、E2E 报告、性能报告、安全报告和已知限制。
- 不通过条件：用 mock 页面替代真实链路，或故障只能通过重启全部服务恢复。

### Day 20：08-02，6 小时，第一节点毕业考试

- 闭卷原理 60 分钟：画完整架构与数据时序，回答异步、DI、事件、WS/SSE、状态机、Agent loop、幂等和安全问题。
- 现场编码 90 分钟：关闭 AI，增加一种诊断事件并贯通合同、后端、前端和测试。
- 故障排查 60 分钟：从未知现象出发，用日志和 Trace 定位一个实时链路 Bug 和一个 Agent Bug。
- 项目验收 60 分钟：教师随机触发异常、断开连接、重复事件和危险工具请求。
- 答辩 60 分钟：解释关键取舍、失败案例、性能数据、AI diff 审查和后续架构演进。
- 评分复盘 30 分钟：归档证据、确认是否准入 Day 21，并生成补弱清单。
- 不通过条件：只能演示功能，无法解释原理；无法在关闭 AI 后修改核心链路；证据不可复核。

## 6. 第一节点评分标准

第一节点满分 100 分，最低通过线 70 分，项目求职作品线 80 分。

| 独立编码与调试 | 20 | 关闭 AI 后能扩展事件合同、修复异步/状态/Agent 问题 |

- 核心代码无法解释，视为没有掌握；AI 生成代码量不计分。

## 7. 完成路线后的合理预期分

“完成”必须指所有项目里程碑、原理反证、架构门禁、测试和独立考试都高质量通过，而不是把功能列表打勾。全部要求真正达成后的应得分为 **88-92 分**；一般达标执行的现实预测为 82-85 分：

- 项目功能做完但原理说不清：最高 69 分。
- 原理能讲但没有真实项目闭环：最高 69 分。
- 项目闭环、原理、测试达到基本门槛：约 78-82 分。
- 能独立排障，并提供安全、性能、Trace 和有效架构证据：约 82-87 分。
- 所有计划项高质量完成，架构答辩能应对约束变化：约 88-92 分。
- 达到 90 分以上还需要明显超出计划的设计质量和独立问题解决能力。

当前正式分仍为待评。Day 1 产生入学基线，Day 10 产生中期分，Day 20 才产生第一节点正式分。

## 8. 每日评分方法

每天满分 100：项目证据 70 分 + 五连问 30 分。项目证据包括项目增量 25、独立编码 15、测试与反证 15、安全/可靠性 10、提交和复盘 5；五问包括局部机制、边界一致性、线上事故、工程权衡、架构演进，各 6 分。

当天通过必须同时满足：总分至少 70、项目证据至少 49/70、五连问至少 21/30、每题至少 4/6。连续两天未通过，暂停新增功能并补考。

教师不按教程时长、页面数量、AI 对话长度或生成代码行数评分，只按可运行项目、原理解释、反例测试和独立排障证据评分。
